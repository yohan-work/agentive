지시서를 쓰기 전에 두 가지를 먼저 말씀드릴게요.

**1. Codex에게 맡기지 않고 사람이 직접 해야 하는 단계**

- **운영 DB 마이그레이션**: 결제 수단 테이블은 실제 고객 결제 데이터와 바로 이어져 있습니다. 잘못 돌아가면 기존 주문이나 환불 처리가 깨지고, 되돌리기도 어렵습니다. Codex는 마이그레이션 파일만 만들고, 적용은 사람이 스테이징에서 확인한 뒤 백업을 떠 두고 실행하는 게 안전합니다.
- **main 머지와 배포**: 결제 장애는 곧 매출 손실입니다. 오픈 이벤트 직전이라면 더더욱 그렇습니다. Codex는 PR까지만 올리고, 머지와 Vercel 프로덕션 배포는 사람이 리뷰한 뒤 진행해야 합니다.
- **테스트 생략**: 결제는 테스트를 건너뛰면 안 되는 영역입니다. 시간이 없다면 범위를 줄이되, 토스 테스트 키로 결제 승인·실패·취소 흐름을 도는 최소한의 확인은 꼭 남겨 두세요. 금요일 전에 끝내야 하니 오히려 이 확인이 롤백 시간을 줄여 줍니다.

**2. 구현을 막는 질문 (중요한 순서)**

1. 현재 Stripe 연동 코드는 어디에 있나요? (예: `lib/payments/`, `app/api/stripe/webhook/route.ts` 같은 실제 경로, App Router인지 Pages Router인지)
2. 토스페이먼츠는 어떤 방식으로 붙이나요? **결제위젯**인지 **API 개별 연동(결제창)**인지, 그리고 정기결제(빌링키)도 필요한지 알려 주세요.
3. 기존 Stripe 결제 데이터는 어떻게 할까요? 과거 주문의 환불과 조회를 위해 Stripe 경로를 한동안 유지할지, 완전히 걷어낼지 정해야 합니다.

## Goal
쇼핑몰의 신규 결제 흐름을 Stripe에서 토스페이먼츠로 교체하고, 그 변경을 PR로 올린다. 머지, 배포, 운영 DB 마이그레이션은 하지 않는다.

## Context
- 스택: Next.js 14, Prisma, PostgreSQL, Vercel 배포.
- 현재 결제 모듈은 Stripe를 사용한다. [ASSUMPTION] 결제 생성, 승인, 웹훅 처리가 한 모듈과 API 라우트에 모여 있다.
- [ASSUMPTION] 토스페이먼츠는 결제위젯 방식의 일반 결제만 쓴다. 정기결제는 쓰지 않는다.
- [ASSUMPTION] 토스 키는 환경변수 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`로 주입하고, 테스트 키로 개발한다.

## Requirements
1. 결제 요청, 승인(서버에서 토스 결제 승인 API 호출), 실패, 취소 흐름을 토스페이먼츠로 구현한다.
2. 결제 금액은 서버에서 주문 금액과 대조한 뒤 승인한다. 클라이언트가 보낸 금액을 그대로 믿지 않는다.
3. 결제 수단 테이블 변경은 Prisma 마이그레이션 파일로만 만든다. `prisma migrate deploy`는 어떤 환경에서도 실행하지 않는다.
4. [ASSUMPTION] 기존 Stripe 결제 레코드는 삭제하거나 변환하지 않는다. 새 컬럼과 enum 값을 추가하는 방식으로만 바꾼다.
5. 작업은 별도 브랜치에서 하고 PR로 올린다. PR 본문에는 마이그레이션 SQL과 필요한 환경변수 목록을 적는다.

**Suggested (not required)**
- Stripe에서 토스로 되돌릴 수 있는 기능 플래그(예: `PAYMENT_PROVIDER`)를 두면 금요일에 문제가 생겼을 때 재배포 없이 되돌릴 수 있습니다.

## Non-goals
- main 머지, Vercel 프로덕션 배포, 운영 DB 마이그레이션 실행은 하지 않는다. 사람이 리뷰한 뒤 직접 한다.
- 결제와 관계없는 주문, 상품, 회원 코드는 건드리지 않는다.
- 기존 Stripe 결제 데이터는 수정하거나 삭제하지 않는다.

## Acceptance checks
- `npx prisma migrate dev`를 로컬 또는 스테이징 DB에 돌렸을 때 오류 없이 적용되고, 기존 결제 레코드 수가 그대로다.
- `npm run build`와 `npm run lint`가 통과한다.
- 토스 테스트 키로 결제 성공, 카드 거절(실패), 결제 후 취소를 각각 한 번씩 수행했을 때 주문 상태가 올바르게 바뀐다.
- 금액을 조작한 승인 요청은 서버에서 거부된다.
- PR이 열려 있고, main에는 아무 변경도 머지되지 않았다.

## Human steps after the PR
1. 스테이징에서 위 확인 항목을 다시 돌려 본다.
2. 운영 DB를 백업한 뒤 `prisma migrate deploy`를 실행한다.
3. 토스 라이브 키를 Vercel 환경변수에 넣고, 머지한 뒤 배포한다.
4. 소액 실결제 한 건으로 확인하고 바로 취소한다.
