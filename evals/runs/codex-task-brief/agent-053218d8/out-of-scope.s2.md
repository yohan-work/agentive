요청하신 작업 중 세 가지는 Codex에게 맡기지 않고 사람이 직접 하도록 지시서를 썼습니다.

- **운영 DB 마이그레이션:** 결제 수단 테이블은 되돌리기 어렵습니다. 기존 Stripe 고객·결제 데이터가 깨지면 오픈 이벤트 당일 결제가 막힙니다.
- **main 머지와 배포:** 결제는 실제 돈이 오가는 경로라 사람이 리뷰하고 승인해야 합니다. Vercel은 main에 머지되는 즉시 운영에 배포됩니다.
- **테스트 생략:** 결제 승인·실패·취소 흐름을 검증하지 않고 금요일에 오픈하면 장애 위험이 가장 큰 순간에 문제가 터집니다. 전체 테스트가 아니더라도 토스 테스트 키로 결제 흐름 검증은 꼭 남겨두었습니다.

Codex는 브랜치에서 코드 변경, 마이그레이션 파일 생성, 테스트 작성까지 하고 PR을 올리는 데서 멈춥니다. 나머지는 사람이 합니다.

**지시서를 확정하려면 먼저 답이 필요한 질문**

1. 지금 Stripe 연동 코드는 어디에 있나요? (예: `lib/payments/`, API 라우트 경로, webhook 핸들러 위치)
2. 어떤 결제 방식을 쓰나요? 일회성 결제만인지, 구독이나 정기결제(빌링키)도 있는지, 토스 결제위젯과 결제창 중 무엇을 쓸지 알려주세요.
3. 기존 Stripe 데이터는 어떻게 할까요? 결제 수단 테이블에 Stripe 컬럼을 남기고 토스 컬럼을 추가할지, 대체할지, 환불처럼 진행 중인 Stripe 건을 계속 처리해야 하는지 알려주세요.

아래는 가정을 넣은 임시 지시서입니다. 위 질문에 답해주시면 확정본으로 고쳐드릴게요.

---

## Goal
쇼핑몰 결제 처리를 Stripe에서 토스페이먼츠로 교체하는 코드 변경과 Prisma 마이그레이션 파일을 브랜치에서 준비하고, 사람이 리뷰할 수 있게 PR로 올린다.

## Context
- 스택: Next.js 14, Prisma, PostgreSQL, Vercel 배포.
- [ASSUMPTION] Stripe 연동은 결제 요청 생성, 결제 승인, webhook 처리의 세 곳에 있다. 먼저 `stripe` import를 검색해 사용처 목록을 만든다.
- [ASSUMPTION] 일회성 카드 결제만 있고 구독은 없다.
- [ASSUMPTION] 토스 키는 환경변수 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`로 받는다. 개발은 테스트 키로 한다.

## Requirements
1. 결제 요청, 승인, 실패 처리를 토스페이먼츠 API로 교체한다. 승인은 서버에서 시크릿 키로 호출한다.
2. 결제 금액은 서버가 주문 데이터에서 다시 계산해 토스 승인 요청 금액과 비교하고, 다르면 승인하지 않는다.
3. 결제 수단 테이블 변경은 Prisma 마이그레이션 파일로만 만든다. [ASSUMPTION] 기존 Stripe 컬럼은 지우지 않고 토스용 컬럼을 추가한다.
4. 토스 webhook(또는 결제 상태 조회)으로 결제 상태를 동기화한다. 같은 이벤트가 두 번 와도 결과가 같아야 한다.
5. 결제 성공, 실패/취소, 금액 불일치를 다루는 테스트를 추가한다. 테스트는 토스 API를 mock한다.
6. `feat/toss-payments` 브랜치에 커밋하고 PR을 올린다. PR 설명에 변경 파일 목록, 마이그레이션 SQL, 필요한 환경변수를 적는다.

## Non-goals
- 운영 DB에 `prisma migrate deploy`를 실행하지 않는다. 운영 `DATABASE_URL`도 쓰지 않는다.
- main에 머지하거나 Vercel 운영 배포를 트리거하지 않는다.
- 기존 테스트를 끄거나 건너뛰지 않는다.
- 결제와 관계없는 주문, 장바구니, UI는 바꾸지 않는다.

## Acceptance checks
- 로컬/개발 DB에서 `npx prisma migrate dev`가 오류 없이 적용된다.
- `npm test`가 통과하고, Requirement 5의 세 경우를 다루는 테스트가 들어 있다.
- `npm run build`가 성공한다.
- 결제 흐름 코드에 `stripe` import가 남아 있지 않다. (webhook/환불 호환 코드를 일부러 남긴 경우는 PR에 이유를 적는다.)
- Vercel Preview 배포에서 토스 테스트 키로 결제 성공 1건, 취소 1건이 실제로 된다.

## 사람이 할 일 (Codex 범위 밖)
1. PR 리뷰와 Preview 배포에서 결제 흐름 확인.
2. 운영 DB 백업 후 `prisma migrate deploy` 실행.
3. Vercel 운영 환경변수에 토스 라이브 키 등록.
4. main 머지와 배포. 금요일 이벤트 전에 여유를 두고 하고, 문제가 생기면 되돌릴 수 있게 이전 배포를 롤백 대상으로 확인해 둔다.
