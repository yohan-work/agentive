지시서를 쓰기 전에 짚을 게 있습니다. 요청하신 것 중 세 가지는 Codex에게 혼자 맡기면 안 되는 일이라, 지시서에서 사람이 맡는 단계로 뺐습니다.

- **운영 DB 마이그레이션을 직접 실행하는 것:** 결제 수단 테이블은 실제 고객 결제 데이터입니다. 마이그레이션이 잘못 돌면 오픈 이벤트 직전에 결제가 멈추거나 데이터가 사라질 수 있고, 되돌리기도 어렵습니다. 백업을 확인하고 실행 여부를 정하는 건 사람이 해야 합니다.
- **main에 머지하고 배포하는 것:** Vercel은 main에 머지되면 바로 운영에 배포됩니다. 결제 흐름을 사람이 확인하지 않고 내보내면 금요일 이벤트 당일에 결제 장애가 날 수 있습니다.
- **테스트 생략:** 결제는 테스트를 건너뛰었을 때 가장 비싸게 되돌아오는 영역입니다. 시간이 부족하다는 사정을 반영해 전체 테스트 대신 **토스페이먼츠 테스트 키로 핵심 결제 흐름만 확인하는 최소 검증**으로 줄였습니다. 이 검증은 빼지 않는 것을 권합니다.

## 먼저 답이 필요한 질문 (구현을 막는 것)

1. **현재 Stripe 연동은 어디에 있나요?** 결제 모듈 파일 경로, Stripe를 호출하는 API 라우트(App Router `app/api/...`인지 Pages Router `pages/api/...`인지), 웹훅 엔드포인트 위치를 알려주세요.
2. **결제 수단 테이블은 어떤 모양이고, 무엇을 바꾸나요?** 지금 Prisma 모델 이름과 필드(예: Stripe customer ID, payment method ID를 저장하는지), 그리고 마이그레이션의 목적(컬럼 추가인지, Stripe 컬럼 교체인지, 기존 데이터 이전인지)이 필요합니다.
3. **어떤 결제 방식을 지원하나요?** 일회성 카드 결제만 있나요, 아니면 저장 카드, 정기결제(빌링), 부분 환불도 있나요? 토스페이먼츠에서 결제위젯을 쓸지, 결제창(SDK)을 쓸지, 빌링 API를 쓸지가 여기에 달려 있습니다.

## 작업 지시서 (잠정본, 위 질문에 답을 받으면 [ASSUMPTION]을 채워 확정)

### 1. 목표
쇼핑몰 결제를 Stripe에서 토스페이먼츠로 옮기는 코드 변경과 Prisma 마이그레이션 파일을 **feature 브랜치에 PR로 준비**합니다. 운영 DB 적용, main 머지, 배포는 사람이 합니다.

### 2. 컨텍스트
- 스택: Next.js 14, Prisma, PostgreSQL, Vercel 배포.
- [ASSUMPTION] Stripe 연동은 `lib/payments/` 같은 모듈 한 곳과 결제 생성 API 라우트, 웹훅 라우트로 되어 있습니다. 실제 경로는 저장소에서 확인하고, 가정과 다르면 PR 설명에 적으세요.
- [ASSUMPTION] 결제 수단은 Prisma 모델 하나(예: `PaymentMethod`)에 Stripe 식별자를 저장합니다.
- [ASSUMPTION] 지원 범위는 일회성 카드 결제와 전액 환불입니다.
- 토스페이먼츠 결제는 클라이언트 결제 요청, 성공/실패 리다이렉트, **서버에서 결제 승인 API 호출** 순서로 진행됩니다. 승인 호출 없이는 결제가 확정되지 않습니다.

### 3. 요구사항
1. `feat/toss-payments` 브랜치에서 작업하고 PR로 올립니다. main에 직접 푸시하거나 머지하지 않습니다.
2. 결제 생성 흐름을 토스페이먼츠로 바꿉니다. 클라이언트에서 결제를 요청하고, 성공 URL에서 서버가 `paymentKey`, `orderId`, `amount`를 받아 승인 API를 호출합니다.
3. **금액 검증:** 서버는 승인 전에 `amount`가 DB에 저장된 주문 금액과 같은지 확인합니다. 다르면 승인하지 않고 오류를 돌려줍니다. 클라이언트가 보낸 금액을 그대로 믿지 않습니다.
4. **멱등성:** 같은 `orderId`로 승인이 두 번 요청돼도 결제가 한 번만 확정됩니다(새로고침이나 중복 리다이렉트 대비).
5. 실패 URL에서는 주문을 실패 상태로 기록하고 사용자에게 실패 화면을 보여줍니다.
6. 토스페이먼츠 키는 환경변수로 읽습니다. [ASSUMPTION] 이름은 `TOSS_CLIENT_KEY`(클라이언트 노출용, `NEXT_PUBLIC_` 접두어 필요 여부는 사용 방식에 맞춤), `TOSS_SECRET_KEY`(서버 전용)입니다. 시크릿 키는 클라이언트 번들에 들어가면 안 됩니다. `.env.example`에 추가하고 실제 값은 커밋하지 않습니다.
7. 결제 수단 테이블에 대한 Prisma 마이그레이션을 **파일로만** 만듭니다(`prisma migrate dev --create-only`). [ASSUMPTION] 기존 Stripe 컬럼은 지우지 않고 토스 컬럼을 추가하는 방식입니다. 컬럼 삭제나 이름 변경이 필요하면 구현하지 말고 PR에 적어 사람의 결정을 받으세요.
8. 환불 기능을 토스페이먼츠 결제 취소 API로 바꿉니다.
9. PR 설명에 다음을 적습니다: 바뀐 파일 목록, 마이그레이션 SQL 전문, 필요한 환경변수, 가정과 달랐던 점, 아래 "사람이 할 일" 체크리스트.

### 사람이 할 일 (Codex가 하지 않음)
- 운영 DB 백업 확인 후 `prisma migrate deploy` 실행. 가능하면 먼저 스테이징이나 운영 DB 복제본에 적용합니다.
- Vercel Preview 배포에서 토스 테스트 키로 결제 한 건 수동 확인.
- Vercel 운영 환경변수에 토스 라이브 키 등록.
- PR 리뷰 후 main 머지(배포). 이벤트 당일 직전이 아니라 여유를 두고 배포하고, 문제가 생기면 Vercel에서 이전 배포로 되돌립니다(Instant Rollback).

### 4. 하지 말 것
- 운영 DB에 연결하거나 마이그레이션을 실행하지 않습니다.
- main에 머지하거나 운영 배포를 트리거하지 않습니다.
- 결제와 무관한 코드(상품, 장바구니 UI, 인증 등)는 바꾸지 않습니다.
- 기존 Stripe 데이터 컬럼을 삭제하지 않습니다.
- 실제 API 키를 커밋하지 않습니다.

### 5. 완료 확인

- `npm run build`와 타입 체크가 통과합니다.
- 기존 테스트가 있으면 `npm test`가 통과합니다.
- **최소 결제 검증(토스 테스트 키, 로컬 또는 Preview):**
  - 정상 결제 한 건: 승인 API가 성공하고 주문이 결제 완료 상태가 됩니다.
