지시서를 쓰기 전에 짚을 게 있습니다. 요청하신 것 가운데 세 가지는 Codex에게 맡기지 않고 사람이 직접 하도록 지시서에 넣었습니다.

- **운영 DB 마이그레이션을 바로 실행하는 것**: 결제 수단 테이블은 실제 주문·결제 데이터와 연결되어 있습니다. 마이그레이션이 잘못되면 데이터가 손상되거나 결제가 멈추는데, Codex는 백업을 확인하거나 되돌릴 판단을 할 수 없습니다.
- **main에 머지하고 배포하는 것**: 결제 코드는 사람이 리뷰하지 않은 상태로 오픈 이벤트 직전에 운영에 나가면 안 됩니다. 문제가 생기면 매출 손실로 바로 이어집니다.
- **테스트를 생략하는 것**: 일정이 빠듯할수록 결제 흐름 테스트가 더 중요합니다. 금요일에 결제가 실패하면 테스트에 드는 시간보다 훨씬 큰 손실이 납니다. 최소한 토스 테스트 키로 핵심 흐름은 확인하도록 넣었습니다.

그래서 Codex는 **브랜치에서 구현하고, 마이그레이션 파일을 만들고, 테스트 환경에서 검증한 뒤 PR을 올리는 데까지** 맡고, 운영 DB 적용·머지·배포는 사람이 하도록 나눴습니다.

## 먼저 답이 필요한 질문

1. **현재 Stripe 연동은 어디에 있고 범위가 어디까지인가요?** 결제 관련 파일이나 디렉터리 경로, 사용하는 기능(단건 결제, 정기결제/구독, 환불, 웹훅)을 알려주세요.
2. **토스페이먼츠는 어떤 방식으로 연동하나요?** 결제위젯인지 API 개별 연동인지, 그리고 테스트 키와 라이브 키가 이미 발급됐는지 알려주세요.
3. **결제 수단 테이블은 어떻게 바꿔야 하나요?** 현재 Prisma 모델 이름과 바꿀 컬럼을 알려주시고, 기존 Stripe 결제·환불 데이터를 그대로 둘지(병행 보관) 옮길지도 정해주세요.

답을 주시면 아래 가정들을 확정해서 지시서를 다시 정리해 드리겠습니다.

## 작업 지시서 (임시본, [ASSUMPTION] 표시는 확인 필요)

### 1. 목표
쇼핑몰 결제 모듈을 Stripe에서 토스페이먼츠로 바꾸고, 결제 수단 테이블 마이그레이션 파일을 작성해서 리뷰 가능한 PR로 올린다. 운영 DB 적용, 머지, 배포는 하지 않는다.

### 2. 컨텍스트
- 스택: Next.js 14, Prisma, PostgreSQL, Vercel 배포.
- 현재 Stripe로 결제를 처리하고 있다.
- [ASSUMPTION] Stripe 연동 코드는 한 모듈에 모여 있고, 결제 생성·승인·웹훅 처리를 한다. 경로는 질문 1의 답으로 채운다.
- [ASSUMPTION] 토스페이먼츠 결제위젯을 쓰고, 테스트 키는 환경변수 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`로 받는다.
- [ASSUMPTION] 기존 Stripe 결제 기록은 조회용으로 남기고, 신규 결제만 토스로 처리한다.

### 3. 요구사항
1. 새 브랜치에서 작업한다(예: `feat/toss-payments`).
2. 신규 결제의 생성과 승인이 토스페이먼츠 API로 처리된다.
3. 토스 결제 결과(성공/실패) 콜백을 처리해서 주문 상태를 갱신한다.
4. 결제 수단 테이블 변경은 Prisma 마이그레이션 파일로 작성한다. **로컬이나 테스트 DB에만 적용하고 운영 DB에는 실행하지 않는다.**
5. [ASSUMPTION] 환불(결제 취소)도 토스 API로 처리한다.
6. API 키는 환경변수로만 읽고, 코드나 커밋에 넣지 않는다.
7. 토스 테스트 키로 결제 성공, 결제 실패, 환불 흐름을 확인하는 테스트를 추가한다.
8. PR 설명에 마이그레이션 내용(추가·변경·삭제되는 컬럼, 기존 데이터에 미치는 영향)과 롤백 방법을 적는다.

**Suggested (not required)**
- 환경변수 플래그로 Stripe와 토스를 전환할 수 있게 해서 문제가 생기면 즉시 되돌릴 수 있도록 한다.
- 토스 웹훅(가상계좌 입금 등)을 처리한다. 결제 수단에 가상계좌가 있을 때만 해당한다.

### 4. Non-goals
- 운영 DB에 마이그레이션을 실행하지 않는다.
- main에 머지하거나 Vercel 운영 배포를 하지 않는다.
- 기존 Stripe 결제 기록을 삭제하거나 변경하지 않는다.
- 결제와 무관한 코드(상품, 장바구니 UI 등)는 건드리지 않는다.

### 5. 수락 기준
- `npx prisma migrate dev`가 로컬/테스트 DB에서 오류 없이 적용된다.
- `npm run build`가 통과한다.
- 새로 추가한 결제 테스트(`npm test` 또는 프로젝트의 테스트 명령)가 모두 통과한다.
- 토스 테스트 키로 로컬에서 결제하면 주문 상태가 결제 완료로 바뀌고, 결제 실패와 환불도 각각 올바른 상태로 바뀐다.
- PR이 올라가 있고, 설명에 마이그레이션 영향과 롤백 방법이 적혀 있다.

### 6. 사람이 할 일 (Codex 작업 이후)
1. PR 코드 리뷰
2. 운영 DB 백업 확인 후 `npx prisma migrate deploy` 실행
3. Vercel Preview 배포에서 토스 테스트 키로 결제 흐름 확인
4. Vercel 운영 환경변수에 라이브 키 등록, main 머지, 배포
5. 배포 직후 실제 소액 결제와 환불로 최종 확인

금요일 오픈 이벤트까지 여유를 두려면 늦어도 목요일 오전에는 PR 리뷰를 시작하는 걸 권합니다.
