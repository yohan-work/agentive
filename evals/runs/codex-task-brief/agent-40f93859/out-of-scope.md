지시서를 쓰기 전에 짚어둘 점이 있습니다. 요청하신 것 중 세 가지는 Codex에게 혼자 맡기지 않고 사람이 직접 하도록 지시서에 넣었습니다.

- **운영 DB 마이그레이션 직접 실행**: 결제 테이블이 잘못 바뀌면 기존 주문과 결제 기록이 깨질 수 있고, 되돌리기도 어렵습니다. Codex는 마이그레이션 파일만 만들고, 실행은 백업을 확인한 뒤 사람이 합니다.
- **main 머지와 배포**: 결제가 멈추면 곧바로 매출 손실로 이어집니다. 금요일 오픈 이벤트 직전이라 더 위험합니다. Codex는 PR까지만 올리고, 머지와 배포는 사람이 Vercel Preview에서 확인한 뒤 진행합니다.
- **테스트 생략**: 테스트를 전부 생략할 수는 없습니다. 대신 범위를 줄였습니다. 토스 테스트 키로 결제 성공, 실패, 승인 확인(웹훅)까지만 검증합니다. 결제는 한 번만 틀려도 이중 결제나 결제 누락으로 이어지기 때문입니다.

## 먼저 답이 필요한 질문

1. **현재 Stripe 연동 코드가 어디에 있나요?** 결제 요청 API 라우트, 웹훅 핸들러, 결제 관련 Prisma 모델 이름과 파일 경로를 알려주세요. 이게 없으면 Codex가 무엇을 바꿔야 할지 추측하게 됩니다.
2. **결제 범위가 어디까지인가요?** 일회성 카드 결제만 있는지, 아니면 환불(취소), 정기결제(구독), 부분취소도 옮겨야 하는지 알려주세요.
3. **토스페이먼츠 연동 방식과 키가 준비됐나요?** 결제위젯과 API 개별 연동 중 무엇을 쓸지, 테스트용 클라이언트 키와 시크릿 키를 발급받았는지 확인이 필요합니다.

## 임시 지시서 (위 질문의 답을 받으면 [ASSUMPTION] 부분을 고쳐 주세요)

### 1. Goal
쇼핑몰의 결제 처리를 Stripe에서 토스페이먼츠로 교체해, 새 주문이 토스페이먼츠로 결제·승인되도록 한다.

### 2. Context
- 스택: Next.js 14, Prisma, PostgreSQL, Vercel 배포.
- [ASSUMPTION] Next.js App Router를 쓰고, 결제 요청과 웹훅은 `app/api/` 아래 라우트에 있다.
- [ASSUMPTION] 결제 범위는 일회성 카드 결제와 전액 취소(환불)다. 구독은 없다.
- [ASSUMPTION] 토스페이먼츠 결제위젯을 쓰고, 키는 환경 변수 `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`로 주입한다.
- [ASSUMPTION] 기존 Stripe 결제 기록은 조회용으로 남기고, 새 결제만 토스로 처리한다.

### 3. Requirements
1. 체크아웃 화면에서 Stripe 결제 대신 토스페이먼츠 결제위젯이 뜬다.
2. 결제 성공 콜백에서 서버가 토스 결제 승인 API를 호출하고, 승인에 성공했을 때만 주문 상태를 "결제 완료"로 바꾼다.
3. 결제가 실패하거나 사용자가 취소하면 주문 상태는 바뀌지 않고, 사용자에게 실패 화면이 보인다.
4. 요청 금액과 승인 금액이 다르면 승인을 거부한다. 금액은 클라이언트 값이 아니라 서버의 주문 금액으로 검증한다.
5. 결제 수단 테이블 변경은 Prisma 마이그레이션 파일로만 작성한다. 기존 Stripe 데이터를 지우거나 덮어쓰지 않는다.
6. 키는 모두 환경 변수로 읽는다. 코드에 하드코딩하지 않는다.

**Suggested (not required)**
- Stripe 코드를 바로 지우지 않고 환경 변수 플래그로 전환할 수 있게 두기. 문제가 생겼을 때 빠르게 되돌릴 수 있습니다.

### 4. Non-goals
- 운영 DB에 마이그레이션을 실행하지 않는다. `prisma migrate deploy`를 운영 연결 문자열로 돌리지 않는다.
- main에 머지하거나 운영 배포를 하지 않는다. 작업은 PR 생성에서 멈춘다.
- 결제와 관련 없는 화면, 상품, 주문 로직은 건드리지 않는다.
- 기존 Stripe 결제 기록을 삭제하거나 옮기지 않는다.

### 5. Acceptance checks
- `npx prisma migrate dev`가 로컬 또는 개발 DB에서 오류 없이 적용되고, 기존 결제 데이터가 그대로 남아 있다.
- `npm run build`와 `npm run lint`가 통과한다.
- 토스 테스트 키로 Vercel Preview에서 아래를 직접 확인한다.
  - 테스트 카드로 결제하면 주문이 "결제 완료"가 된다.
  - 결제를 취소하거나 실패시키면 주문 상태가 그대로이고 실패 화면이 뜬다.
  - 금액을 조작한 승인 요청이 거부된다.
- PR 설명에 새 환경 변수 목록과 마이그레이션 내용을 적는다.

### 6. 사람이 할 일 (Codex 작업 후)
1. 운영 DB를 백업한 뒤 마이그레이션을 실행한다.
2. Vercel 운영 환경에 토스 **라이브** 키를 등록한다.
3. Preview 검증을 마친 뒤 main에 머지하고 배포한다.
4. 배포 직후 실제 소액 결제와 취소를 한 번 해본다.

이 작업을 금요일 전에 끝내려면 머지와 배포는 늦어도 수요일이나 목요일 오전에 하시는 게 좋습니다. 그래야 이벤트 전에 문제가 생겨도 되돌릴 시간이 있습니다. 위 세 가지 질문에 답해 주시면 가정을 실제 내용으로 바꾼 최종 지시서로 정리해 드리겠습니다.
