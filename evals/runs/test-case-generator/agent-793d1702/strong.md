# /agents 검색·필터 회귀 테스트 매트릭스 (PR #19 한국어화 기준)

말씀해 주신 동작 명세만으로 매트릭스를 만들 수 있어서 바로 작성했습니다. 명세에서 비어 있는 부분은 아래 "가정"에 적었습니다. 판단이 필요한 항목은 "기대결과"에 **[결정 필요]**로 표시했습니다. 맨 끝의 확인 질문 4개에 답해 주시면 해당 행을 확정하겠습니다.

---

## 1. 범위와 표기

- **대상 경로**: `/en/agents`, `/ko/agents` (로컬 `npm run dev`와 GitHub Pages 배포본)
- **뷰포트**: 모바일 375px, 데스크톱 1440px
- **우선순위**
  - P0: 릴리스를 막는 항목. 매 회귀 때 실행합니다.
  - P1: 주요 흐름. 매 회귀 때 실행합니다.
  - P2: 엣지 케이스와 사양 확인. 분기 1회 또는 관련 코드가 바뀔 때 실행합니다.
- **자동화 후보 열**
  - **U**: `src/lib/search.ts` 함수 단위로 node:test에 옮길 수 있습니다.
  - **M**: 수동으로만 확인할 수 있습니다(UI, URL, 렌더링).
  - **U+M**: 로직은 단위 테스트로, 표시는 수동으로 확인합니다.
- **공통 전제조건 약칭**
  - `P-KO` / `P-EN`: 해당 경로를 로드해 JS 하이드레이션이 끝난 상태입니다. 검색어와 필터가 비어 있고 "100개 중 100개 표시"가 보입니다.
  - `ORC`: 기대 건수를 적은 오라클 시트입니다(3장 참고).

---

## 2. 가정

1. 검색은 로케일과 무관합니다. `/en`과 `/ko`에서 같은 haystack(에이전트 원본 필드)을 씁니다. 따라서 **ko UI에 보이는 번역 라벨**(예: 카테고리 한국어명)은 haystack에 들어 있지 않습니다. 한국어로 매칭되는 것은 realUseCases의 한국어 텍스트뿐입니다.
2. 필터 비교는 원시 값(`intermediate`, `tested`, 슬러그 등)으로 합니다. 번역은 칩 라벨에만 적용됩니다.
3. 역할·카테고리·도구처럼 배열인 필드는 "선택한 값이 배열에 포함되면 일치"로 처리합니다.
4. "설치 가능"은 `installTargets`가 1개 이상인 경우입니다. `installTargets: []`는 설치 불가로 봅니다.
5. 페이지 안 검색창에 입력한 값은 URL에 쓰지 않습니다. 따라서 새로고침하면 URL의 `?query=` 값으로 돌아갑니다.
6. 검색은 입력할 때마다 반영됩니다(Enter가 필요 없음). 디바운스가 있는지는 모릅니다.
7. 총 개수 "100"은 하드코딩이 아니라 전체 에이전트 수에서 계산됩니다.

## 3. 테스트 데이터 준비 (오라클 시트)

기대 건수 N을 화면이 아닌 **원본 데이터에서 따로 집계해 둬야** 회귀를 잡을 수 있습니다. 한 번 만들어 두고 에이전트 데이터가 바뀔 때만 갱신합니다.

| 오라클 키 | 내용 |
|---|---|
| ORC-A | 기준 에이전트 A: 이름으로 검색했을 때 **정확히 1건**만 나오는 에이전트 |
| ORC-F | tags, categories, roles, tools, summary, description, realUseCases(ko) 각각에**만** 들어 있는 단어 1개씩과 해당 에이전트 |
| ORC-D | 난이도 3값별 건수(합계 100) |
| ORC-L | 자동화 수준 1~5별 건수(합계 100) |
| ORC-V | 검증 상태 4값별 건수(합계 100) |
| ORC-I | 설치 가능 20건 목록 |
| ORC-C | 2~3개 교집합 조합 5개의 기대 건수. 결과가 0건인 조합 1개를 반드시 포함합니다 |

## 5. 단위 테스트로 옮길 후보

자동화 열이 **U**인 행 가운데 먼저 옮길 것을 추리면 다음과 같습니다.

| 묶음 | 대상 ID | 비고 |
|---|---|---|
| 검색 정규화 | SR-01~09, SR-11, KO-02~07 | 작은 픽스처(5~8건)로 테이블 기반 테스트 |
| 필터 조건 | FL-01~06, FL-08, FL-10~11 | 필터별 조건을 개별로 검증 |
| 조합 | CB-01~04, CB-09, RG-03 | 교집합과 순서 무관성 |
| 실데이터 불변식 | FL-02~05, RG-05 | 실제 100건 데이터로 "합계=100", "설치 가능=20" 확인. 데이터가 바뀌면 깨지므로 숫자 대신 `agents.length`나 오라클 파일을 기준으로 삼는 것을 권장 |
| (search.ts 밖) | RG-02 | 사전 키 동일성. 같은 node:test 러너로 import할 수 있다면 비용 대비 효과가 가장 큼 |

예시 골격입니다. 함수 이름과 시그니처는 실제 `search.ts`에 맞게 바꿔 주세요.

```ts
// search.test.ts (node --import tsx --test)
import { test } from "node:test";
import assert from "node:assert/strict";
import { filterAgents } from "../src/lib/search"; // 가정한 이름

const fx = [
  { slug: "a", name: "Code Reviewer", summary: "PR review", installTargets: ["claude"], difficulty: "beginner", /* ... */ realUseCases: ["코드 리뷰 자동화"] },
  { slug: "b", name: "Doc Writer", summary: "docs", installTargets: [], difficulty: "advanced", /* ... */ realUseCases: [] },
];

const cases: [string, string, string[]][] = [
  ["빈 검색은 전체", "", ["a", "b"]],
  ["공백만은 전체", "   ", ["a", "b"]],
  ["대소문자 무시", "CODE", ["a"]],
  ["trim", "  review  ", ["a"]],
  ["한국어 realUseCases", "리뷰", ["a"]],
  ["특수문자 리터럴", ".*", []],
];

for (const [name, query, expected] of cases) {
  test(name, () => {
    const got = filterAgents(fx, { query, filters: {} }).map((a) => a.slug);
    assert.deepEqual(got, expected);
  });
}

test("installTargets: [] 는 설치 가능에서 제외", () => {
  const got = filterAgents(fx, { query: "", filters: { installable: true } }).map((a) => a.slug);
  assert.deepEqual(got, ["a"]);
});
```
