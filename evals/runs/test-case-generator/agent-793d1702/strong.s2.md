# /agents 검색·필터 회귀 테스트 매트릭스 (PR #19 한국어화 기준)

## 1. 요약

- 총 68개 케이스, 8개 분류. P0 28개 / P1 26개 / P2 14개.
- **단위 테스트 후보(U)**: 29개(토글·교체 로직을 분리하면 +2). `src/lib/search.ts`의 순수 함수(검색 문자열 생성, 매칭, 필터 적용, 옵션 목록 생성)로 검증 가능한 것만 골랐습니다.
- **수동 전용(M)**: URL/새로고침, IME 입력, 번역 라벨, 반응형, EmptyState 표시는 E2E 도구가 없으니 QA가 수동으로 확인합니다.
- 추가 정보 없이 바로 쓸 수 있게 작성했습니다. 다만 실제 데이터에 따라 기대결과 숫자가 달라지는 케이스는 "데이터 기준표"(5절)를 한 번 채워 두면 QA가 합격/불합격을 바로 판정할 수 있습니다.

### 표기

| 표기 | 의미 |
|---|---|
| KO / EN | `/ko/agents`, `/en/agents`에서 JS 로드(하이드레이션)까지 끝난 초기 상태. 검색어 없음, 필터 없음 |
| 기준표 | 5절 데이터 기준표에 적어 둔 키워드와 기대 개수 |
| P0 | 릴리스 차단. 매 PR 회귀 때 실행 |

| P2 | 엣지 케이스·현재 동작 기록용. 분기 1회 또는 관련 코드 변경 시 실행 |
| U / M | U = 단위 테스트로 옮길 후보, M = 수동 |

## 2. 가정

1. 검색 시 **입력값도 소문자화**한 뒤 `includes`로 비교한다고 가정했습니다(검색 대상만 소문자화한다면 SR-02가 실패해야 정상입니다).
2. 검색 대상 문자열(haystack)은 **로케일과 상관없이 같습니다**. 영문 데이터 필드에 `realUseCases`의 한국어 텍스트가 더해진 형태이고, UI에 보이는 한국어 카테고리/역할 표시명은 들어 있지 않다고 가정했습니다(KO-02 참고).
3. 각 에이전트는 난이도·자동화 수준·검증 상태를 **정확히 하나씩** 가진다고 가정했습니다. 그래서 값별 결과 수의 합이 100이어야 합니다.
4. "설치 가능" = `installTargets`가 존재하고 **비어 있지 않은** 배열입니다(현재 20개).
5. 결과 카운트의 분모 "100"은 하드코딩된 값이 아니라 `agents.length`에서 나온다고 가정했습니다.
6. `search.ts`에는 대략 `buildSearchText(agent)`, `matchesQuery(agent, query)`, `filterAgents(agents, query, filters)`, `getToolOptions(agents)` 같은 함수가 있거나 이렇게 분리할 수 있다고 가정했습니다. 이름은 실제 코드에 맞게 바꿔 주세요.
7. 필터 상태는 컴포넌트 로컬 상태이고 로케일을 전환하면 초기화된다고 가정했습니다. 확인이 필요해서 KO-10에서 "현재 동작 기록"으로 처리했습니다.

## 4. 단위 테스트로 옮길 후보 (node:test + tsx)

실데이터에 의존하는 테스트는 데이터가 바뀔 때마다 깨지므로, **작은 픽스처(에이전트 6~8개) 기반 테스트**를 중심으로 하고 실데이터에는 불변식 스모크 테스트만 두는 것을 권합니다.

| 묶음 | 포함 케이스 | 픽스처 포인트 |
|---|---|---|
| 검색 매칭 | SR-01~09, KO-01, KO-02, KO-04, KO-05 | 필드별로 서로 다른 고유 단어, 한국어 realUseCases 1개, 특수문자가 들어간 description 1개 |
| 단일 필터 | FL-01~08, FL-10, FL-11 | 자동화 수준을 숫자로 저장, `installTargets`를 `undefined`/`[]`/`["claude-code"]` 세 가지로 |
| 조합 | CB-01~04, EM-01 | 교집합이 1개, 0개가 되는 조합을 각각 준비 |
| 옵션 목록 | FL-05 | `"GitHub"`, `"github"`, `"Notion"`, 중복 항목 |
| 불변식/사전 | RG-04~06 | 실데이터, `dictionaries.ts` |

FL-10, FL-11(토글/교체)과 CB-05, CB-06(초기화)은 지금 컴포넌트 안에 있다면 수동으로 확인해야 합니다. `nextFilters(prev, key, value)`, `clearFilters(state)` 같은 순수 함수로 빼면 단위 테스트로 옮길 수 있습니다.

예시 골격:

```ts
import { test } from "node:test";
import assert from "node:assert/strict";
import { filterAgents } from "../src/lib/search";
import { fixtureAgents } from "./fixtures/agents";

test("query is trimmed and case-insensitive", () => {
  const a = filterAgents(fixtureAgents, "  REVIEW ", {});
  const b = filterAgents(fixtureAgents, "review", {});
  assert.deepEqual(a.map((x) => x.slug), b.map((x) => x.slug));
});

test("empty installTargets is not installable", () => {
  const r = filterAgents(fixtureAgents, "", { installableOnly: true });
  assert.ok(r.every((x) => (x.installTargets?.length ?? 0) > 0));
});
```
