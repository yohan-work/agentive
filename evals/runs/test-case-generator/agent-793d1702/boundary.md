오늘 바로 쓰실 수 있게 지금 정보로 테스트 케이스를 먼저 만들었습니다. 최대 할인 금액은 아직 정해지지 않아서 **`MAX`** 로 비워 두었어요. 기획서에서 값이 나오면 그 자리에 숫자만 넣으면 됩니다.

## 1. 확인이 필요한 사항 (2개)

| # | 질문 | 왜 필요한가 | 답이 오기 전 가정 |
|---|---|---|---|
| Q1 | **최대 할인 금액(`MAX`)** 은 얼마인가요? 정률에만 적용되나요, 정액에도 적용되나요? | 경계값 케이스의 기대 결과가 이 값으로 정해집니다 | 정률에만 적용 |
| Q2 | "중복 사용 가능"은 **같은 쿠폰을 여러 주문에 반복해서 쓸 수 있다**는 뜻인가요? | "한 주문에 하나만"과 같이 놓고 보면 두 가지로 읽힙니다. 쿠폰을 여러 번 쓸 수 있다는 뜻인지, 여러 쿠폰을 겹쳐 쓸 수 있다는 뜻인지에 따라 케이스가 달라집니다 | 여러 주문에 반복 사용은 가능하고, 한 주문에 여러 장을 겹쳐 쓰는 것은 불가 |

Q2의 가정이 틀리면 섹션 3의 **B 그룹 전체**를 다시 봐야 합니다. 이 부분은 먼저 확인해 주세요.

## 2. 가정

- A1. 할인 방식은 정률(%)과 정액(원) 두 가지입니다.
- A2. 할인 금액은 원 단위로 계산하고, 정률 계산에서 생기는 원 미만은 **버림**합니다. (기획 확인 필요)
- A3. 할인 금액은 주문 금액을 넘을 수 없고, 결제 금액은 0원 밑으로 내려가지 않습니다.
- A4. 쿠폰 유효기간, 최소 주문 금액, 적용 대상 상품 같은 조건은 이번 요청에 없어서 **일반 케이스로만** 넣었습니다. 해당 조건이 없는 기능이면 N/A로 처리하시면 됩니다.
- A5. 주문을 취소하거나 환불해도 반복 사용 쿠폰이라 별도 복원 절차는 없다고 가정합니다.

## 3. 테스트 케이스 매트릭스

우선순위: **P1** = 반드시 오늘 실행 / **P2** = 가능하면 실행 / **P3** = 여유 있을 때

### A. 할인 계산: 정액

| ID | 시나리오 | 입력 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| A-01 | 정액 기본 적용 | 주문 50,000원, 정액 5,000원 | 할인 5,000 / 결제 45,000 | P1 |
| A-02 | 할인액 = 주문 금액 | 주문 5,000원, 정액 5,000원 | 할인 5,000 / 결제 0 | P1 |
| A-03 | 할인액 > 주문 금액 | 주문 3,000원, 정액 5,000원 | 할인 3,000 / 결제 0 (음수 금지) | P1 |
| A-04 | 정액에 `MAX` 적용 여부 | 정액 > `MAX`인 쿠폰 | Q1 답변에 따라 결정 | P2 |

### A. 할인 계산: 정률 (`MAX` 경계값)

| ID | 시나리오 | 입력 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| A-11 | 정률 기본 적용 (상한 미도달) | 주문 금액 × 율 < `MAX` | 할인 = 주문 금액 × 율 | P1 |
| A-12 | **상한 경계 -1원** | 계산 할인액 = `MAX` - 1 | 할인 = `MAX` - 1 | P1 |
| A-13 | **상한 경계 정확히** | 계산 할인액 = `MAX` | 할인 = `MAX` | P1 |
| A-14 | **상한 경계 +1원** | 계산 할인액 = `MAX` + 1 | 할인 = `MAX` (상한 적용) | P1 |
| A-15 | 상한 크게 초과 | 고액 주문 | 할인 = `MAX` | P1 |
| A-16 | 원 미만 절사 | 주문 9,999원, 10% | 할인 999 (A2 가정 기준) | P2 |
| A-17 | 100% 쿠폰 | 주문 10,000원, 100% | 할인 = min(10,000, `MAX`) | P2 |
| A-18 | 0% 또는 비정상 율 | 0%, 음수, 100% 초과 | 쿠폰 생성 또는 적용 단계에서 차단 | P3 |

> A-12~A-14 입력값 만드는 법: 10% 쿠폰에 `MAX` = 10,000원이면 주문 금액을 99,990원 / 100,000원 / 100,010원으로 잡으면 됩니다. `MAX`가 정해지면 같은 방식으로 역산하세요.

### B. 사용 규칙: 한 주문에 하나 + 반복 사용

| ID | 시나리오 | 기대 결과 | 우선순위 |
|---|---|---|---|
| B-01 | 한 주문에 쿠폰 1장 적용 | 정상 적용 | P1 |
| B-02 | 한 주문에 쿠폰 2장 적용 시도 (UI) | 두 번째 쿠폰 선택 불가, 또는 기존 쿠폰이 교체됨 | P1 |
| B-03 | 한 주문에 쿠폰 2장 적용 시도 (API 직접 호출) | 서버에서 거절 | P1 |
| B-04 | 같은 쿠폰으로 두 번째 주문 | 정상 적용 (반복 사용 가능) | P1 |
| B-05 | 같은 쿠폰으로 주문 여러 건 연속 (3건 이상) | 매번 정상 적용, 할인액 동일 | P2 |
| B-06 | 적용한 쿠폰을 다른 쿠폰으로 교체 | 마지막에 선택한 쿠폰 1장만 반영, 금액 재계산 | P1 |
| B-07 | 쿠폰 적용 후 해제 | 할인 0, 원래 금액으로 복귀 | P2 |
| B-08 | 두 탭이나 기기에서 같은 쿠폰으로 동시에 결제 | 두 주문 모두 정상 처리 (반복 사용 가능이므로) | P2 |
| B-09 | 한 주문 결제 요청을 동시에 두 번 보냄 (쿠폰 1장) | 주문 1건만 생성되고 할인도 1번만 적용 | P2 |

## 4. 권장 사항

1. **오늘은 P1(17개)부터 실행하세요.** 금액 계산 오류와 쿠폰 여러 장 적용이 사고로 이어질 가능성이 가장 큽니다.
2. `MAX` 경계값 케이스(A-12~A-14)는 기획서가 오면 **바로 숫자를 채워서 실행**하세요. 나머지 케이스는 `MAX` 없이도 지금 진행할 수 있습니다.

4. 반복 사용이 가능한 쿠폰은 한 번 유출되면 계속 쓰일 수 있습니다. 사용 횟수나 기간 제한이 정말 없는지 기획에 한 번 더 확인해 보세요.
