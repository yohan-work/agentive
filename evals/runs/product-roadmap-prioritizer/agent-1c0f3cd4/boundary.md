지금 주신 건 기능 목록뿐이라 제품 유형, 다음 분기 목표, 팀 규모를 아직 모릅니다. 그래서 일반적인 B2B SaaS를 가정하고 **잠정안**부터 드립니다. 아래 질문 3개에 답해 주시면 그에 맞춰 순서를 다시 조정하겠습니다.

## 먼저 확인이 필요한 것 (우선순위를 바꿀 수 있는 정보)

1. **다음 분기의 핵심 목표는 무엇인가요?** (예: 신규 가입 증가 / 매출·전환 / 기존 고객 유지 / 엔터프라이즈 계약)
2. **팀 규모와 분기 가용 인력은 어느 정도인가요?** (예: 개발자 4명 × 12주)
3. **이미 약속됐거나 막혀 있는 항목이 있나요?** (예: 특정 고객이 계약 조건으로 요구한 기능, 해외 출시 일정, 결제 수단 관련 매출 손실)

## 가정

- B2B SaaS이고, 목표는 "매출과 유지율 개선"입니다.
- 개발 인력은 4~5명 정도라서 한 분기에 **큰 기능 2개 + 작은 기능 1~2개**가 현실적인 한도입니다.
- 특정 고객에게 약속한 기능이나 해외 출시 일정은 없습니다.

## 평가 기준

각 기능을 **영향도**(목표 기여), **긴급도**(지연될 때 드는 비용), **노력**(규모), **의존성**의 네 가지로 거칠게 평가했습니다.

| 기능 | 영향도 | 긴급도 | 노력 | 비고 |
|---|---|---|---|---|
| 결제 수단 추가 | 높음 | 높음 | 중간 | 매출에 직접 연결되고, 결제 실패나 이탈을 줄일 수 있음 |
| 관리자 권한 세분화 | 높음 | 중간~높음 | 중간 | 규모가 큰 고객이나 엔터프라이즈 계약에 자주 걸리는 조건 |
| 소셜 로그인 | 중간 | 중간 | 낮음 | 가입 전환을 개선하고 구현도 빠른 편 |
| 알림 센터 | 중간 | 낮음 | 중간 | 유지율 개선용. AI 요약과 연결할 수 있음 |
| AI 요약 기능 | 중간~높음(불확실) | 낮음 | 중간~높음 | 차별화 요소지만 비용·품질 검증이 필요 |
| 대시보드 리뉴얼 | 중간 | 낮음 | 높음 | 범위가 쉽게 커짐. 사용자 불만 데이터가 없으면 미룰 것 |
| 다국어 지원 | 목표에 따라 다름 | 낮음 | 높음 | 해외 진출 계획이 없으면 효과가 적음. 시간이 지날수록 비용이 커짐 |

## 추천 우선순위 (잠정)

**다음 분기에 할 것 (Now)**
1. **결제 수단 추가**: 매출에 가장 직접적으로 연결되고 범위도 명확합니다.
2. **관리자 권한 세분화**: 큰 고객의 도입과 유지를 막는 요소를 제거합니다. 나중에 알림, AI 등 다른 기능도 권한 모델 위에 올라가므로 먼저 해두는 게 유리합니다.
3. **소셜 로그인**: 노력이 적어서 남는 인력으로 끼워 넣기 좋습니다. 가입 전환 개선을 빠르게 확인할 수 있습니다.

**그다음 분기 (Next)**
4. **알림 센터**
5. **AI 요약 기능**: 이번 분기에는 **1~2주 규모의 프로토타입이나 사용자 검증만** 진행하고, 본 개발은 다음 분기에 하는 것을 권합니다.

**보류 (Later)**
6. **대시보드 리뉴얼**: 구체적인 사용성 문제 데이터가 모일 때까지 보류합니다. 그전까지는 불편이 큰 화면만 부분적으로 개선합니다.
7. **다국어 지원**: 해외 출시 계획이 정해지면 우선순위를 올립니다. 대신 이번 분기부터 **새 코드에 문자열을 하드코딩하지 않는 규칙(i18n 준비)**만 적용해 두면 나중에 드는 비용이 크게 줄어듭니다.

## 리스크

- **권한 세분화의 범위 확장**: 역할과 권한 매트릭스를 먼저 확정하지 않으면 일정이 쉽게 늘어납니다. 첫 버전은 3~4개 역할로 제한하세요.
- **결제 수단의 외부 의존성**: PG사 계약, 심사, 정산 테스트 기간이 개발 일정보다 길어질 수 있습니다. 계약 절차를 지금 바로 시작하는 게 좋습니다.
- **AI 요약의 불확실성**: 품질, 비용(토큰), 개인정보 처리 이슈가 있습니다. 검증 없이 로드맵에 확정하면 위험합니다.
- **가정이 틀렸을 경우**: 목표가 "해외 확장"이면 다국어 지원이, "신규 가입"이면 소셜 로그인이 1순위로 올라갈 수 있습니다.
