좋습니다. 다만 먼저 솔직하게 말씀드리면, 지금은 **귀사의 온보딩이 실제로 어떻게 진행되는지**(사용하는 도구, 단계, 담당자, 고객 유형)에 대한 정보가 없어서 "모든 예외 상황까지 포함한 완성본"을 바로 드릴 수는 없습니다. 제가 추측으로 채우면 그럴듯해 보이지만 실제 업무와 어긋나는 SOP가 되고, 신입이 그걸 믿고 혼자 처리하다가 더 큰 문제가 생길 수 있습니다.

그래서 아래 두 가지를 드립니다.

1. **바로 쓸 수 있는 SOP 뼈대(초안)** — 일반적인 B2B/서비스 고객 온보딩 기준으로 작성했고, `[ ]` 부분을 귀사 내용으로 채우면 됩니다.
2. **완성도를 높이기 위해 필요한 질문 목록** — 답해 주시면 귀사 맞춤 SOP로 다시 정리해 드리겠습니다.

## 1. 고객 온보딩 SOP (초안)

### 문서 정보
- **목적:** 신규 계약 고객이 계약 후 [N]영업일 안에 서비스를 정상적으로 사용하기 시작하도록 한다.
- **적용 범위:** [신규 계약 고객 전체 / 특정 플랜 이상] 
- **담당:** 온보딩 담당자(이하 "담당자")
- **승인/에스컬레이션 대상:** [팀장 이름/역할], [기술 지원 담당], [영업 담당]
- **최종 수정일 / 작성자:** [ ]

### 사용 도구
| 용도 | 도구 | 접근 권한 확인 |
|---|---|---|
| 고객 정보·계약 | [CRM 예: HubSpot, Salesforce] | ☐ |
| 작업 추적 | [예: Jira, Asana, 스프레드시트] | ☐ |
| 커뮤니케이션 | [이메일, Slack, 카카오톡 채널 등] | ☐ |
| 계정 생성 | [관리자 콘솔 URL] | ☐ |
| 결제 확인 | [결제 시스템] | ☐ |

> 신입은 첫날 위 도구 전부에 로그인이 되는지 먼저 확인하세요. 권한이 없으면 온보딩을 시작하지 말고 [팀장]에게 요청합니다.

### 표준 절차

**0단계. 인계 받기 (D+0)**
1. [CRM]에서 "계약 완료" 상태로 바뀐 고객을 확인한다.
2. 영업 인계 메모에서 다음을 확인한다: 고객사명, 담당자 이름·연락처, 계약 플랜, 시작일, 특이 요청사항.
3. 빠진 항목이 있으면 → **예외 A** 참고.
4. [작업 추적 도구]에 온보딩 카드를 만들고 체크리스트 템플릿을 붙인다.

**1단계. 결제·계약 확인 (D+0)**
1. [결제 시스템]에서 결제 완료 또는 청구서 발행 여부를 확인한다.
2. 결제 미완료 → **예외 B** 참고.

**2단계. 환영 연락 (D+0 ~ D+1)**
1. 환영 이메일 템플릿 [링크]을 보낸다. 포함 내용: 담당자 소개, 전체 일정, 킥오프 미팅 일정 제안, 준비물 목록.
2. 1영업일 안에 답이 없으면 → **예외 C** 참고.

**3단계. 계정 생성·설정 (D+1 ~ D+2)**
1. [관리자 콘솔]에서 고객 계정을 만든다. 플랜 설정이 계약 내용과 같은지 두 번 확인한다.
2. 고객 관리자에게 초대 메일을 보낸다.
3. 고객이 요청한 초기 설정([예: 사용자 추가, 연동, 데이터 이관])을 체크리스트대로 진행한다.
4. 오류 발생 → **예외 D** 참고.

**4단계. 킥오프 / 교육 (D+2 ~ D+5)**
1. 킥오프 미팅을 진행한다. 아젠다 템플릿 [링크] 사용.
2. 기본 사용법 교육 후 자료 [링크]를 공유한다.
3. 미팅 메모를 [CRM]에 기록한다.

**5단계. 사용 시작 확인 (D+5 ~ D+14)**
1. 고객이 [핵심 행동 예: 첫 로그인, 첫 프로젝트 생성]을 했는지 확인한다.
2. 안 했다면 → **예외 E** 참고.

**6단계. 종료·인계 (D+14 ~ D+30)**
1. 온보딩 완료 체크리스트를 모두 체크한다.
2. 고객에게 완료 안내와 이후 지원 채널을 안내한다.
3. [CRM] 상태를 "온보딩 완료"로 바꾸고 [CS/계정 관리 담당]에게 인계한다.

### 예외 상황 처리

| 코드 | 상황 | 신입이 할 일 | 혼자 판단하지 말고 넘길 기준 |
|---|---|---|---|
| A | 영업 인계 정보 누락 | 영업 담당에게 요청 후 기다림 (고객에게 추측으로 연락하지 않음) | 1영업일 넘게 답이 없으면 [팀장] |
| B | 결제 미완료 | 계정 생성 보류, 영업/재무에 알림 | 고객이 "먼저 열어 달라"고 요청하면 반드시 [팀장] 승인 |
| C | 고객 무응답 | D+1, D+3에 재연락(이메일→전화), 기록 남김 | 5영업일 무응답이면 영업 담당에게 알림 |
| D | 계정/설정 오류 | 오류 화면 캡처, 재현 절차 기록 후 [기술 지원]에 티켓 | 고객 데이터 손실·보안 우려가 있으면 **즉시** [팀장]+[기술 지원] |
| E | 사용 시작 안 함 | 짧은 확인 연락, 추가 교육 제안 | 2주 넘게 미사용이면 [계정 관리 담당] |
| F | 계약에 없는 요청 (추가 기능, 할인, 일정 변경) | "확인 후 안내드리겠다"고만 답함 | **항상** 영업 담당 또는 [팀장] — 신입이 약속하지 않음 |
| G | 고객 불만·해지 언급 | 내용 그대로 기록, 공감 표현만 | **항상 즉시** [팀장] |
| H | 고객 측 담당자 변경 | 새 담당자 확인, CRM 업데이트 | 권한 이관(관리자 변경)은 [팀장] 확인 후 |
| I | 위 표에 없는 상황 | 아무것도 확정하지 않고 기록 | **항상** [팀장]에게 질문 |

> 핵심 원칙: **돈, 계약 조건, 보안, 고객 데이터**와 관련된 건 신입이 혼자 결정하지 않습니다. 나머지는 이 문서대로 진행하고, 애매하면 물어봅니다.

### 완료 체크리스트
- ☐ 인계 정보 확인
- ☐ 결제 확인
- ☐ 환영 메일 발송
- ☐ 계정 생성 및 플랜 설정 재확인
- ☐ 초기 설정 완료
- ☐ 킥오프/교육 진행 및 기록
- ☐ 핵심 사용 행동 확인
- ☐ 완료 안내 및 인계

## 2. 귀사 맞춤으로 완성하려면 알려 주세요

1. **어떤 서비스/제품**의 온보딩인가요? (SaaS, 에이전시 서비스, 금융, 교육 등)
2. 현재 온보딩은 **누가, 어떤 순서로** 하고 있나요? 지금 하는 분이 평소에 하는 일을 순서대로 적어만 주셔도 됩니다.
3. 사용하는 **도구**는 무엇인가요? (CRM, 계정 관리 콘솔, 메신저 등)
4. 고객 유형별로 절차가 **다른 경우**가 있나요? (플랜, 규모, 국내/해외 등)
5. 지금까지 **실제로 자주 생긴 문제나 예외**는 뭐였나요? 이게 예외 목록을 채우는 가장 중요한 재료입니다.
6. 신입이 **절대 혼자 하면 안 되는 일**과 **물어볼 사람**은 누구인가요?
7. 템플릿(메일, 미팅 아젠다, 체크리스트)이 이미 있나요?

## 한 가지 현실적인 조언

어떤 SOP도 "모든 예외"를 미리 담을 수는 없습니다. 신입이 내일부터 혼자 하게 하려면 문서보다 다음 두 가지가 더 효과적입니다.

- **첫 1~2건은 기존 담당자가 옆에서 함께 보기** (또는 신입이 하고 담당자가 검토)
- 예외 표의 **마지막 줄(I: 표에 없는 상황 → 물어보기)을 명확히 해 두고**, 새로 생긴 예외는 그때마다 SOP에 추가하기

위 질문에 답을 주시면, 귀사 실제 절차에 맞춰 이 초안을 바로 고쳐 드리겠습니다.
