# 고객 온보딩 SOP (v0.1 초안)

## 0. 이 문서 사용법
- **목적:** 신규 고객이 계약 후 [ ]일 안에 서비스를 정상 사용하도록 만든다.
- **대상:** 온보딩 담당자(신입 포함)
- **원칙:**
  - 각 단계의 **완료 기준**을 충족하기 전에는 다음 단계로 넘어가지 않는다.
  - 문서에 없는 상황, 또는 판단이 애매하면 **추측하지 말고 에스컬레이션**한다. (연락처: 11번)
  - 모든 고객 커뮤니케이션과 진행 상태는 [CRM/티켓 시스템 이름]에 기록한다.
- **초기 운영 권장:** 입사 후 첫 [2주]는 각 단계 완료 시 선임([이름])에게 체크 요청.

## 3. 단계별 절차

### 3-1. 인수인계 확인 (D+0, 소요 약 [30분])
1. 영업 인수인계 메모를 확인한다.
2. 계약서의 **플랜, 사용자 수, 시작일, 특약사항**을 CRM 정보와 대조한다.
3. 고객사 담당자 이름·연락처·이메일을 확인한다.
- **완료 기준:** CRM에 고객 레코드가 생성되고, 계약 내용과 일치함.

### 3-2. 환영 연락 (D+0 ~ D+1)
1. 템플릿 [환영 메일 템플릿 위치]로 환영 메일을 보낸다.
2. 킥오프 미팅 일정을 제안한다 (후보 시간 2~3개).
- **완료 기준:** 고객이 메일을 수신 확인했거나, 킥오프 일정이 확정됨.

### 3-3. 계정 생성 및 권한 설정 (D+1 ~ D+2)
1. [시스템]에서 고객 계정을 생성한다.
2. 계약된 플랜/사용자 수에 맞게 설정한다.
3. 관리자 계정 초대 메일을 발송한다.
- **완료 기준:** 고객 관리자가 첫 로그인에 성공함.

### 3-4. 킥오프 미팅 (D+2 ~ D+5)
1. 체크리스트: 목표 확인, 일정 공유, 고객 측 필요 자료 요청, 다음 단계 안내.
2. 미팅 후 24시간 이내에 회의록과 할 일 목록을 고객에게 발송한다.
- **완료 기준:** 회의록 발송 및 CRM 기록.

### 3-5. 데이터 이관 / 연동 / 초기 설정 (해당 시, D+5 ~ D+[ ])
1. 고객에게 필요한 자료(데이터 파일, API 키 등)를 요청한다.
2. 수신 자료를 [검증 방법]으로 확인한다.
3. 설정/이관 후 고객과 함께 결과를 확인한다.
- **완료 기준:** 고객이 결과를 확인하고 이상 없음을 회신함.

### 3-6. 사용 교육 (D+[ ])
1. 기본 사용 교육 진행 (자료: [ ]).
2. 도움말/지원 채널을 안내한다.
- **완료 기준:** 고객 측 주요 사용자가 핵심 기능 [ ]을 직접 수행해 봄.

### 3-7. 온보딩 종료 및 인계 (D+[ ])
1. 종료 확인 메일 발송 + 만족도 설문.
2. 운영/CS 담당자에게 인계하고 CRM 상태를 "온보딩 완료"로 변경한다.
- **완료 기준:** CRM 상태 변경, 인계 메모 작성.

아래 정보를 주시면 빈칸을 채우고, 귀사 상황에 맞는 예외 케이스로 다시 정리해 드릴게요.

1. **업종과 서비스 형태** (예: SaaS, 에이전시, 교육, 금융 등)
2. **현재 온보딩 순서** – 대략적인 메모나 기존 담당자가 하는 방식을 그대로 적어주셔도 됩니다.
3. **사용하는 도구** (CRM, 계약/결제, 메신저, 티켓 시스템 등)
4. **실제로 자주 문제가 됐던 사례** 3~5개 – 이게 "예외 처리"의 핵심입니다.
5. **신입의 권한 범위** – 어디까지 혼자 결정해도 되는지
6. **목표 기간** (계약 후 며칠 안에 온보딩 완료가 목표인지)
7. **규제/보안 요건** (개인정보, 금융 규제 등 해당 여부)

**현실적인 팁 하나:** 내일 바로 쓰려면, 오늘 기존 담당자가 이 초안을 15~30분 정도 훑어보며 빈칸과 틀린 부분만 표시해 주는 것만으로도 품질이 크게 올라갑니다. 그리고 신입이 처음 몇 건을 진행하면서 막혔던 지점을 4번 예외 표에 계속 추가하면, 몇 주 안에 실제로 "모든 예외"에 가까운 문서가 됩니다.
