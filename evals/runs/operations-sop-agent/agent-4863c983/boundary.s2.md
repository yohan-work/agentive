좋습니다. 먼저 솔직하게 말씀드리면, 지금 주신 정보만으로는 **"신입이 내일부터 혼자 할 수 있는" 수준의 SOP는 만들 수 없습니다.** 귀사의 온보딩이 실제로 어떤 단계로 진행되는지, 어떤 도구를 쓰는지, 어떤 예외가 실제로 발생하는지를 모르기 때문입니다. 제가 추측으로 채운 "모든 예외 상황"은 그럴듯해 보여도 실제 현장과 어긋날 가능성이 높고, 신입이 그걸 믿고 혼자 처리하면 오히려 위험합니다.

그래서 아래 두 가지를 드립니다.

1. **꼭 필요한 질문 (답해 주시면 실제 SOP로 완성)**
2. **바로 쓸 수 있는 SOP 골격 초안** (가정 기반, 빈칸 표시)

---

## 1. 필요한 정보 (필수 질문)

아래만 답해 주시면 됩니다. 짧게 적어 주셔도 충분합니다.

1. **고객 유형과 범위**: 어떤 고객을 온보딩하나요? (예: B2B SaaS 기업 고객, 개인 회원, 대리점 등) 온보딩의 시작과 끝은 어디인가요? (예: 계약 체결 → 첫 사용/첫 결제 완료)
2. **현재 진행 단계**: 지금 실제로 하고 있는 작업을 순서대로 나열해 주세요. (예: 환영 메일 발송 → 계정 생성 → 킥오프 미팅 → 데이터 이관 → 교육 → 인수인계)
3. **사용 도구/시스템**: CRM, 어드민 페이지, 결제 시스템, 메일/메신저 등 무엇을 쓰고, 신입에게 어떤 권한이 있나요?
4. **실제로 자주 발생하는 예외 3~5개**: 과거에 문제가 됐던 케이스들 (예: 고객 담당자 연락 두절, 서류 누락, 결제 실패, 계약 조건과 다른 요청 등)
5. **에스컬레이션 대상**: 신입이 판단할 수 없을 때 누구에게, 어떤 채널로 넘기나요?
6. **기준 시간(SLA)**: 각 단계를 며칠/몇 시간 안에 끝내야 하나요?

## 2. SOP 골격 초안 (가정 기반)

> 아래는 일반적인 B2B 고객 온보딩을 **가정**하고 만든 틀입니다. `[ ]`로 표시된 부분은 귀사 정보로 채워야 합니다.

### 2.1 개요
- **목적**: 신규 고객이 계약 후 [N]일 안에 서비스를 정상적으로 사용하기 시작하도록 한다.
- **적용 범위**: [고객 유형]의 신규 계약 건. (재계약·업셀은 제외)
- **담당**: 온보딩 담당자(신입 포함). 승인/예외 판단: [팀 리드 이름/역할]
- **완료 기준**: [예: 고객이 첫 로그인 + 핵심 기능 1회 사용 + 담당자 인수인계 완료]

### 2.2 사전 준비 (신입이 첫날 확인할 것)
- [ ] [CRM] 접근 권한
- [ ] [어드민] 계정 생성 권한
- [ ] 환영 메일/안내 문서 템플릿 위치: [링크]
- [ ] 에스컬레이션 채널: [예: 슬랙 #onboarding-help]

### 2.3 표준 절차

| 단계 | 작업 | 도구 | 기한 | 완료 확인 |
|---|---|---|---|---|
| 1 | 계약 정보 확인 (플랜, 인원, 시작일, 특이 조건) | [CRM] | 계약 당일 | 필수 항목 누락 없음 |
| 2 | 고객 계정 생성 및 권한 설정 | [어드민] | D+1 | 테스트 로그인 성공 |
| 3 | 환영 메일 발송 (로그인 정보, 일정 안내) | [메일 템플릿] | D+1 | 발송 기록 CRM에 남김 |
| 4 | 킥오프 미팅 일정 확정 및 진행 | [캘린더] | D+3 이내 | 회의록 CRM 등록 |
| 5 | 초기 설정/데이터 이관 지원 | [ ] | D+7 이내 | 고객 확인 받음 |
| 6 | 사용 교육 | [ ] | D+10 이내 | 교육 참석 기록 |
| 7 | 온보딩 완료 확인 및 담당 부서 인수인계 | [CRM] | D+14 | 상태 "온보딩 완료"로 변경 |

### 2.4 예외 처리 (일반적 예시, 실제 케이스로 교체 필요)

| 상황 | 신입이 할 일 | 에스컬레이션 기준 |
|---|---|---|
| 계약 정보가 누락/불일치 | 진행 멈추고 영업 담당자에게 확인 요청 | 1영업일 내 답 없으면 리드에게 |
| 고객 담당자 연락 두절 | 2일 간격으로 2회 재연락 (메일 + 전화) | 2회 무응답 시 리드/영업에 보고 |
| 계약에 없는 기능·할인·일정 변경 요청 | **약속하지 말 것.** "확인 후 회신드리겠다"고 답변 | 즉시 리드에게 전달 |
| 계정 생성/로그인 오류 | 안내 문서의 기본 조치 확인 | 30분 내 해결 안 되면 [기술지원] |
| 고객 불만·해지 언급 | 내용 그대로 기록, 공감 표현만 | 즉시 리드에게 전달 |
| 개인정보·보안 관련 요청 | 직접 처리 금지 | 즉시 [보안/법무 담당] |
| 위 표에 없는 상황 | 임의 판단하지 말 것 | 리드에게 문의 |

**핵심 원칙**: 신입은 "표에 있는 것만 혼자 처리하고, 나머지는 멈추고 묻는다."

## 가정 (Assumptions)
- B2B 형태의 고객 온보딩이며, 계약 후 약 2주 내 완료를 목표로 한다고 가정했습니다.
- CRM과 어드민 시스템이 있고, 신입에게 계정 생성 권한이 있다고 가정했습니다.
- 에스컬레이션할 리드가 항상 연락 가능하다고 가정했습니다.

## 권고사항 (Recommendations)
- **"모든 예외"를 문서화하려 하지 마세요.** 현실적으로 불가능하고, 문서가 길어지면 신입이 오히려 못 찾습니다. 대신 자주 발생하는 예외 5~7개 + "표에 없으면 멈추고 묻는다" 규칙이 훨씬 안전합니다.
- **첫 주는 혼자 두지 마세요.** 첫 1~2건은 선임과 함께(섀도잉), 다음 2~3건은 신입이 하고 선임이 검토하는 방식으로 넘기는 것을 권합니다.
- 신입이 처리 중 새로 겪은 예외는 예외 표에 계속 추가하도록 하면 SOP가 자연스럽게 채워집니다.

## 리스크 (Risks)
- 제 가정과 실제 프로세스가 다르면, 신입이 잘못된 절차를 따르게 됩니다. **반드시 실무자 검토 후 배포하세요.**
- 계약 외 요청에 신입이 약속하는 경우 → 금전/법적 문제로 이어질 수 있습니다.
- 권한 설정이 미리 안 되어 있으면 내일 첫 작업부터 막힙니다.
