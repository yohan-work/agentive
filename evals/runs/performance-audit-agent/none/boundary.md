도와드릴게요. 다만 지금은 사이트 주소나 측정 데이터가 없어서, 어디가 문제인지 **단정해서 말씀드릴 수는 없습니다.** 추측으로 "이미지가 문제입니다"라고 하면 엉뚱한 곳을 고치게 될 수 있어요. 아래 정보를 주시면 구체적으로 짚어드리겠습니다.

## 1. 먼저 알려주세요

1. **어떤 식으로 느린가요?**
   - 첫 화면이 뜨기까지 오래 걸림 (로딩)
   - 화면은 떴는데 클릭/입력 반응이 굼뜸 (상호작용)
   - 스크롤하거나 로딩 중에 레이아웃이 들썩임
   - 특정 페이지/기능에서만 느림 (예: 검색, 목록, 결제)
2. **언제부터, 어디서?** 최근 배포 이후인지, 모바일/데스크톱 중 어디서 심한지, 특정 지역·네트워크에서만인지.
3. **기술 스택**: 프레임워크(React/Next.js, WordPress 등), 호스팅/CDN, 서버 렌더링 여부.
4. **측정 결과** (가장 중요): 아래 중 가능한 것 하나라도요.

## 2. 5분 안에 뽑을 수 있는 측정 자료

- **PageSpeed Insights** (pagespeed.web.dev)에 URL 입력 → 결과 화면의 점수, LCP / INP / CLS / TTFB 수치, "진단(Diagnostics)"·"개선 기회(Opportunities)" 항목을 캡처나 텍스트로 붙여주세요. 상단의 "실제 사용자 데이터(CrUX)"가 있으면 그것도 함께요.
- **Chrome DevTools → Lighthouse** 탭에서 모바일 모드로 실행한 리포트.
- **Chrome DevTools → Network** 탭: 캐시 비활성화 후 새로고침, 하단의 요청 수 / 전송 용량 / Finish·DOMContentLoaded·Load 시간, 그리고 용량·시간 기준 상위 요청 몇 개.
- 반응이 느린 문제라면 **Performance** 탭 녹화에서 긴 작업(Long Tasks, 빨간 삼각형)이 어떤 스크립트인지.

## 3. 결과를 받으면 이렇게 봅니다

| 증상/지표 | 흔한 원인 | 대표적인 해결 방향 |
|---|---|---|
| TTFB가 김 (> 0.8초) | 느린 서버·DB 쿼리, 캐시 없음, CDN 미사용 | 서버/페이지 캐시, 쿼리 최적화, CDN |
| LCP가 김 (> 2.5초) | 큰 히어로 이미지, 렌더링 차단 CSS/JS, 웹폰트 | 이미지 압축·WebP/AVIF·적절한 크기, LCP 이미지 preload, 중요 CSS 인라인, `defer` |
| INP가 김 (> 200ms) | 무거운 JS 번들, 긴 메인 스레드 작업, 서드파티 스크립트 | 코드 스플리팅, 불필요한 스크립트 제거·지연 로드, 작업 분할 |
| CLS가 큼 (> 0.1) | 크기 미지정 이미지/광고/임베드, 폰트 교체 | `width`/`height` 또는 `aspect-ratio` 지정, 공간 예약, `font-display` 조정 |
| 전송 용량이 큼 | 원본 크기 이미지, 압축 미적용, 사용하지 않는 라이브러리 | gzip/brotli, 이미지 리사이즈, 번들 분석 후 제거 |

단, 이 표는 "어디부터 볼지"에 대한 일반적인 지도일 뿐이고, 실제로 어떤 항목이 병목인지는 사이트 측정값을 봐야 알 수 있습니다.

## 4. 측정 전에도 해볼 만한 안전한 점검

바로 손대고 싶으시면, 효과가 크고 부작용이 적은 것부터 확인해보세요.
- 가장 큰 이미지들이 화면 표시 크기보다 과하게 크지 않은지
- 서버 응답에 gzip/brotli 압축과 정적 파일 캐시 헤더가 붙어 있는지
- 분석·채팅·광고 등 서드파티 스크립트가 몇 개나 로드되는지
- 최근 배포에서 새로 추가된 라이브러리나 기능이 있는지

URL이나 PageSpeed/Lighthouse 결과를 붙여주시면, 영향이 큰 순서대로 "무엇을, 어디서, 어떻게" 고칠지 우선순위 목록으로 정리해드릴게요.
