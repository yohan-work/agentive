도와드릴게요. 다만 지금은 사이트 정보가 전혀 없어서 "어디가 문제"인지 바로 짚어드릴 수는 없습니다. 저는 사이트에 직접 접속하거나 측정할 수 없기 때문에, 아래 자료를 보내주시면 그걸 바탕으로 원인을 좁혀드릴게요.

## 1. 먼저 알려주세요

1. **어떤 느림인가요?**
   - 첫 화면이 뜨기까지 오래 걸림 (초기 로딩)
   - 화면은 떴는데 클릭/입력 반응이 굼뜸 (인터랙션)
   - 스크롤이나 애니메이션이 버벅임
   - 특정 페이지나 특정 기능(검색, 목록, 결제 등)만 느림
2. **언제부터, 누구에게?** 원래 빨랐다가 최근 배포 이후인지, 모바일에서만인지, 특정 지역/네트워크에서만인지
3. **기술 스택**: 프레임워크(React, Next.js, WordPress 등), 호스팅/CDN, 백엔드와 DB
4. **URL** (공개 가능하다면): 제가 직접 열 수는 없지만, 측정 결과를 해석할 때 맥락이 됩니다

## 2. 5분이면 뽑을 수 있는 측정 자료

**가장 유용한 것부터:**

- **PageSpeed Insights** (pagespeed.web.dev)에 URL을 넣고 모바일 결과를 캡처하거나 텍스트로 붙여주세요. 특히 다음 항목이 중요합니다.
  - LCP (최대 콘텐츠 렌더링), INP (상호작용 반응), CLS (레이아웃 흔들림), TTFB (서버 응답 시간)
  - "진단"과 "기회" 섹션 목록
- **Chrome DevTools > Network 탭**: 캐시 비활성화 후 새로고침해서
  - 가장 오래 걸린 요청 상위 5개 (이름, 크기, 시간)
  - 첫 번째 HTML 문서 요청의 "Waiting for server response" 시간
  - 전체 전송량과 요청 수
- **인터랙션이 느린 경우**: DevTools > Performance 탭에서 느린 동작을 녹화하고, 긴 작업(Long Task)에 어떤 함수/스크립트가 찍히는지

## 3. 자료 오기 전에 직접 확인해볼 수 있는 흔한 원인

측정 결과를 기준으로 보면 대체로 이 중 하나에 걸립니다.

| 증상 | 흔한 원인 | 확인 방법 |
|---|---|---|
| TTFB가 높음 (0.8초 이상) | 느린 DB 쿼리, 캐시 없음, 서버 리전이 사용자와 멂, 콜드 스타트 | 서버 로그/APM에서 느린 엔드포인트, 쿼리 실행 계획 |
| LCP가 느림 | 최적화 안 된 대형 이미지, 히어로 이미지 지연 로딩, 렌더링 차단 CSS/폰트 | Network 탭에서 LCP 요소의 크기와 시작 시점 |
| JS가 큼 / INP 나쁨 | 거대한 번들, 불필요한 라이브러리, 서드파티 스크립트(분석, 채팅, 광고) | 번들 분석기, Coverage 탭의 미사용 코드 비율 |
| CLS가 높음 | 크기 지정 없는 이미지/광고/임베드, 웹폰트 교체 | Performance 탭의 Layout Shift 표시 |
| 특정 페이지만 느림 | N+1 쿼리, 페이지네이션 없는 목록, 한 번에 과도한 데이터 조회 | 해당 API 응답 시간과 응답 크기 |
