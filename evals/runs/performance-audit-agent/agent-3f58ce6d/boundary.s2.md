## 먼저 여쭤볼 것 (중요한 순서)

1. **"느리다"는 게 구체적으로 어떤 순간인가요?**
   - 첫 화면이 늦게 뜨나요(흰 화면이 오래 감)?
   - 화면은 떴는데 버튼/입력이 늦게 반응하나요?
   - 로딩 중 레이아웃이 튀나요?
   - 특정 페이지만인가요, 전체인가요? 모바일에서만인가요?
   → 이 답에 따라 봐야 할 지표(LCP / INP / CLS / TTFB)가 완전히 달라집니다.

2. **사이트 URL(또는 가장 느린 페이지 URL)과 기술 스택**
   - 프레임워크(예: Next.js, React SPA, WordPress 등), 렌더링 방식(SSR/SSG/CSR)
   - 호스팅/CDN(예: Vercel, AWS, 자체 서버, Cloudflare 유무)
   - 이미지·폰트·서드파티 스크립트(광고, 분석, 채팅 위젯 등) 사용 여부

3. **제약과 목표**
   - 목표가 있나요? (예: "모바일 LCP 2.5초 이하", "Lighthouse 90점")
   - 바꿀 수 없는 것: 호스팅 변경 불가, 새 라이브러리 추가 불가, SEO 유지 필수 등

## 지금 바로 하실 측정 (이 결과를 붙여주시면 바로 진단합니다)

**A. 실사용자 데이터 (가장 중요)**
- [PageSpeed Insights](https://pagespeed.web.dev/)에 느린 페이지 URL 입력
- 상단 **"실제 사용자 경험(CrUX)"** 섹션의 **모바일** 값: LCP, INP, CLS, TTFB (75번째 백분위)
- 트래픽이 적으면 이 섹션이 비어 있을 수 있는데, 그렇다고 알려주시면 됩니다.

**B. 실험실 측정 (같은 조건으로 3회)**
- Chrome 시크릿 창 → DevTools → Lighthouse 탭
- 설정: **Mobile**, **Performance**만 체크, 기본 제한(Simulated throttling)
- 3번 돌려서 **중간값**의 LCP, TBT, CLS, Speed Index와 함께
- 리포트 하단의 **"LCP 요소"**가 무엇인지(이미지인지 텍스트인지), **"기본 스레드 작업 최소화" / "사용하지 않는 JavaScript 줄이기"** 항목의 상위 3개 파일과 용량

**C. 네트워크 워터폴**
- DevTools → Network 탭 → "Disable cache" 체크, 제한을 **Fast 4G**로 → 새로고침
- 하단의 **요청 수, 전송 용량, DOMContentLoaded, Load** 시간
- 첫 번째 HTML 문서 요청을 클릭 → Timing 탭의 **"Waiting for server response(TTFB)"** 값
- 용량 기준 상위 5개 파일(이름, 크기, 종류)

**D. (반응이 느린 경우만) 상호작용 측정**
- DevTools → Performance 탭 → 녹화 시작 → 느린 버튼 클릭 → 정지
- 클릭 이벤트에 걸린 시간과, 그 구간에서 가장 긴 작업(Long task)의 함수/파일명

## 결과를 받으면 드릴 것

- 각 측정 수치가 가리키는 원인과 근거 (측정으로 확인된 것과 추론을 구분해서)
- 목표 지표에 미치는 영향이 큰 순서의 수정안: 어떤 파일/설정을 어떻게 바꾸는지, 어느 지표가 대략 얼마나 좋아질지(범위와 근거), 위험, 확인 방법
- 수정 전후를 같은 조건으로 비교하는 측정 절차

위 측정 중 A와 B만 먼저 주셔도 1차 진단은 가능합니다.
