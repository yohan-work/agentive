# 오더싱크 고객 의견 정리 (9/15~9/28, 26건)

**한 줄 요약:** 26건 중 **10건(38%)이 "주문을 놓치거나 못 받는" 문제**(알림 5건 + v4.12.0 이후 로그인 풀림 3건 + 피크 시간 접수 지연·튕김 2건)로 모입니다. 해지 사유 1위("주문 누락/알림 문제")와 바로 겹치는 영역이라, 다음 스프린트 15 person-day는 대부분 여기에 쓰는 것을 권합니다.

> 26건은 유료 매장 약 3,800곳 중 일부이고, 문의·리뷰를 남긴 매장만 반영된 표본입니다. 건수는 "얼마나 많은 매장이 겪는지"가 아니라 **신호 강도**로 봐 주세요.

## 2. 테마별 상세

### T1. 주문 알림 미작동·주문 누락 — 5건 (1, 7, 9, 13, 21) · 심각도: 치명

**피드백이 보여주는 것**
- 알림이 안 울리거나 안 들려서 주문을 놓침: 1(쿠팡이츠, 알림음 없음), 7(배민, 볼륨 최대에도 작음), 9(화면 꺼지면 안 울림, 절전 모드 해제 후에도), 21(알림 놓침으로 이번 달 취소 3번)
- 주문 자체가 앱에 안 뜸: 13(쿠팡이츠, 2번, 사장님앱에는 있음)
- 실제 매출 손실이 확인된 건: 1("손님한테 취소당했습니다"), 21("주문 취소 당한 게 이번 달만 3번")

**대표 인용**
- "쿠팡이츠 주문이 알림음 없이 들어와서 20분 동안 몰랐어요. 손님한테 취소당했습니다." (1)
- "주문 누락! 쿠팡이츠 주문이 앱에 아예 안 뜬 적이 2번 있음. 쿠팡 사장님앱엔 있었음." (13)

**심각도 근거:** 제품의 핵심 가치("세 개 앱 따로 안 봐도 돼서", 10번)를 정면으로 깨는 문제이고, 해지 사유 1위와 같은 영역이며, 취소로 인한 금전 손실이 두 건에서 명시됐습니다. 리뷰 ★1·★2로 공개 평판에도 노출됐습니다.

**가능한 원인**
- 9번: 화면 꺼짐 상태에서 알림이 안 울림 → Android 백그라운드 제한/Doze 대응(포그라운드 서비스, 알림 채널 중요도) 문제일 가능성 [ASSUMPTION]
- 7번: 앱 알림 볼륨이 기기 미디어/알림 볼륨 상한에 묶여 있을 가능성 [ASSUMPTION]
- 1, 13번: 둘 다 쿠팡이츠입니다. 9/18 v4.12.0에 **쿠팡이츠 연동 SDK 업데이트**가 포함됐으므로 연관 가능성이 있지만, 두 건의 발생 날짜가 9/18 이전인지 이후인지 피드백에 없어 확정할 수 없습니다 [ASSUMPTION]. 13번은 "알림"이 아니라 "수신" 실패라서 연동 레이어 문제 쪽입니다.
- T2(로그인 풀림)와도 연결됩니다: 아침에 로그아웃된 상태를 모르고 영업을 시작하면 주문이 안 들어오는 것처럼 보일 수 있습니다 [ASSUMPTION].

### T2. v4.12.0 이후 로그인 풀림 — 3건 (3, 15, 22) · 심각도: 높음

**피드백이 보여주는 것**
- 매일 로그아웃됨(3, 15), 비밀번호 저장해도 동일(15), 22번이 "9/18 업데이트(v4.12.0) 이후부터"라고 시점을 특정
- 세 채널(리뷰·전화·앱문의) 모두에서 나옴 → 특정 채널 편향이 아님

**대표 인용**
- "업데이트 후 로그인이 계속 풀려요. 매일 아침 다시 로그인해야 함." (3)
- "로그아웃 문제요. 9/18 업데이트(v4.12.0) 이후부터 그래요." (22)

**심각도 근거:** 배포 직후 생긴 회귀이고 매일 반복되며, v4.12.0 변경 내역에 **"로그인 토큰 저장 방식 변경"**이 있어 원인 후보가 뚜렷합니다. 2주 중 배포 후 10일 동안 3건이 들어왔고, 업데이트한 매장 전체에 영향이 있을 수 있습니다 [ASSUMPTION]. 로그아웃 상태 = 주문 미수신이라면 T1과 같은 해지 위험입니다 [ASSUMPTION].

**가능한 원인:** 토큰 저장 방식 변경으로 리프레시 토큰이 유지되지 않거나 만료 주기가 하루 이내로 짧아졌을 가능성 [ASSUMPTION]. "매일 아침"이라는 패턴은 야간 앱 종료/기기 재시작 후 토큰 소실과 맞아떨어집니다 [ASSUMPTION].

### T3. 점심 피크 때 접수 지연·앱 튕김 — 2건 (2, 18) · 심각도: 높음

**피드백이 보여주는 것**
- 접수 버튼 반응 5초 이상(2), 접수 시 앱 튕김(18)
- 둘 다 점심 시간대: "점심 피크 때"(2), "오후 12시~1시 사이에 특히"(18)
- 기기 정보는 2번만 있음: 갤럭시탭 A7 라이트

**대표 인용**
- "점심 피크 때 주문 접수 버튼 눌러도 반응이 5초 넘게 없음. 태블릿은 갤럭시탭 A7 라이트." (2)
- "주문 접수 누르면 가끔 앱이 튕겨요. 오후 12시~1시 사이에 특히." (18)

**심각도 근거:** 매출이 가장 몰리는 시간에 핵심 동작(접수)이 막힙니다. 접수 지연은 배달앱 쪽 자동 취소나 조리 지연으로 이어질 수 있습니다 [ASSUMPTION].

**가능한 원인:** 피크 시간 서버 응답 지연, 또는 저사양 기기(A7 Lite)에서 주문 다건 동시 처리 시 메모리 부족 [ASSUMPTION]. 18번의 기기와 앱 버전을 모르므로 v4.12.0과의 관련은 불명확합니다.

### T4. 3사 매장 상태 동기화 불완전 — 3건 (11, 12, 19) · 심각도: 중간~높음

**피드백이 보여주는 것**
- 품절 처리가 배민엔 반영되고 쿠팡이츠엔 안 됨(11, 19)
- 영업 종료가 요기요만 따로 처리해야 함(12)
- 19번은 "벌써 세 번째 문의" → 반복 문의, 해결 일정 요구

**대표 인용**
- "메뉴 품절 처리를 여기서 하면 배민에는 반영되는데 쿠팡이츠는 안 돼요." (11)
- "쿠팡이츠 품절 연동 안 되는 거 언제 고쳐지나요? 벌써 세 번째 문의." (19)

**심각도 근거:** 품절이 반영 안 되면 품절 메뉴 주문 → 매장 측 취소 → 배달앱 내 매장 평가 하락으로 이어질 수 있습니다 [ASSUMPTION]. 같은 매장이 세 번 문의했다는 건 CS 응대로 해결이 안 되고 있다는 뜻이고, 불만이 누적되는 유형입니다.

**가능한 원인:** 19번의 "세 번째 문의"로 보아 9/18 이전부터 있던 문제일 가능성이 높아, v4.12.0 SDK 업데이트가 원인은 아닌 것으로 보입니다 [ASSUMPTION]. 쿠팡이츠 API가 품절 연동을 지원하는지, 지원하는데 미구현인지 확인이 먼저입니다.

### T5. 정산 금액 불일치 — 2건 (6, 23) · 심각도: 중간

**피드백이 보여주는 것**
- 쿠팡이츠 수수료가 실제와 다름, "9월 1주 차 기준 8천원 차이"(6)
- 배민 "1주 차 광고비가 빠져 있지 않음"(23)
- 두 건 모두 **9월 1주 차** 데이터 → v4.12.0(9/18) 배포 이전 기간이므로 이번 배포와 무관

**대표 인용**
- "정산 화면에서 쿠팡이츠 수수료가 실제랑 달라요. 9월 1주 차 기준 8천원 차이." (6)
- "정산 금액 안 맞음. 배민 1주 차 광고비가 빠져 있지 않음." (23)

**심각도 근거:** 금액 자체는 작지만 "돈 숫자가 틀린다"는 신뢰 문제이고, 16번(세무사용 월별 매출 엑셀 요청)처럼 정산 데이터를 세무에 쓰려는 수요가 있어 틀린 숫자의 파급이 커질 수 있습니다 [ASSUMPTION].

**가능한 원인:** 수수료율·광고비 항목이 배달앱 쪽 정산 데이터와 다르게 계산되거나 누락됨. 두 앱에서 서로 다른 항목이 틀리므로 공통 원인보다는 앱별 매핑 문제로 보입니다 [ASSUMPTION].

### T6. 영수증 프린터 — 3건 (4, 14, 24) · 심각도: 중간

**피드백이 보여주는 것**
- 연결이 하루 2~3번 끊김, 기종 빅솔론 SRP-350III(4)
- 설정은 1장인데 두 장씩 출력(24)
- 용지 소진 알림 기능 문의(14) — 결함이 아니라 기능 요청

**대표 인용**
- "영수증 프린터(빅솔론 SRP-350III) 연결이 하루에 두세 번 끊겨요." (4)
- "프린터가 주문서 두 장씩 뽑혀요. 설정에서 1장으로 돼 있음." (24)

**심각도 근거:** 주방 운영에 불편을 주지만 주문 자체를 잃는 문제는 아닙니다. 다만 연결 끊김을 모르고 있으면 주문서가 안 나와 조리가 누락될 수 있습니다 [ASSUMPTION].

**가능한 원인:** 4번은 특정 기종·연결 방식(블루투스/USB 등, 피드백에 없음) 문제일 수 있음 [ASSUMPTION]. 24번은 T7의 5번(요기요 알림 두 번)과 같은 "주문 이벤트 중복 처리"일 가능성이 있으나, 24번이 어느 앱 주문인지 적혀 있지 않아 확인 필요 [ASSUMPTION].

### T7. 알림 구분·중복 울림 — 2건 (5, 8) · 심각도: 낮음~중간

**피드백이 보여주는 것**
- 요기요 알림이 두 번 울림, 주문은 한 번만 뜸(5)
- 앱별 알림음을 다르게 하고 싶음, 지금은 어디 주문인지 모름(8)

**대표 인용**
- "요기요 주문 알림이 두 번씩 울림. 같은 주문이 두 번 뜨는 건 아님." (5)
- "알림음 종류를 앱별로 다르게 하고 싶어요. 지금은 다 똑같아서 어디 주문인지 모름." (8)

**심각도 근거:** 주문 손실은 없지만 T1과 같은 알림 영역이라, T1 작업 시 함께 손대면 비용이 적습니다. 8번은 T1의 7번(소리 작음)·21번(진동 요청)과 함께 "알림 설정 개선" 묶음으로 처리 가능합니다.

**가능한 원인:** 5번은 요기요 이벤트 수신이 중복되는데 주문 화면에서만 중복 제거가 되고 알림 트리거에는 적용이 안 된 것일 가능성 [ASSUMPTION].

## 5. 가정과 리스크

**가정**
- 각 문의의 접수 날짜가 없어서, T1의 쿠팡이츠 건(1, 13)이 9/18 이후인지 알 수 없습니다. SDK 업데이트 연관성은 날짜 확인 전까지 가설입니다.
- 로그인 풀림이 주문 미수신으로 이어진다는 연결은 추론이며, 로그아웃 상태에서 앱이 어떻게 보이는지(경고가 뜨는지) 확인이 필요합니다.
- person-day 추정은 모두 제 추정입니다.

**리스크**
- **표본 편향:** 26건은 3,800곳 중 목소리를 낸 매장뿐입니다. 특히 로그인 풀림은 업데이트한 매장 전체의 문제일 수 있어, 문의 3건보다 실제 영향 범위가 훨씬 넓을 수 있습니다.
- **배포 회귀 확산:** v4.12.0이 원인이라면 매장이 업데이트할수록 문의가 늘어납니다. 핫픽스가 늦어질수록 해지 위험이 커집니다.
- **쿠팡이츠 집중:** 26건 중 5건(1, 6, 11, 13, 19)이 쿠팡이츠 관련입니다. 원인은 서로 다를 수 있지만(정산·품절·수신), 매장 입장에서는 "쿠팡이츠 연동이 불안하다"는 인상으로 묶입니다.
- **CS 신뢰:** 반복 문의(19)와 전화 대기(25)가 겹치면, 결함 자체보다 "말해도 안 고쳐진다"가 해지 이유가 될 수 있습니다.
