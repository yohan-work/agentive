고객사에 보낼 릴리스 노트라면 기꺼이 써드릴게요. 다만 쓰기 전에 하나 확인해야 할 게 있습니다.

## 지금 바로 쓸 수 없는 이유

주신 정보는 커밋 해시 네 개(`a1f3c9e`, `77be012`, `3d9e441`, `f02ac18`)뿐인데, 저는 저장소에 접근할 수 없어서 **각 커밋이 무엇을 바꿨는지 알 수 없습니다.** 해시만 보고 내용을 지어내면 고객사에 사실과 다른 내용이 나가게 되니, 그렇게 하지는 않겠습니다.

## 꼭 필요한 정보

**1. 각 커밋의 내용**
가장 쉬운 방법은 아래 명령어 결과를 그대로 붙여 넣어 주시는 거예요.

```bash
git show --stat --format="%h %s%n%b" a1f3c9e 77be012 3d9e441 f02ac18
```

커밋 메시지만 있어도 되고(`git log --oneline`), 메시지가 "fix", "wip"처럼 짧다면 무엇을 바꿨는지 한 줄씩 설명해 주셔도 충분합니다.

**2. 제품/서비스 이름과 버전 번호** (예: "OO 플랫폼 v2.4.0")

## 있으면 더 좋아지는 정보 (없으면 제가 가정하고 표시해 둘게요)

- **배포 일자**: 없으면 "오늘"로 적겠습니다.
- **고객 영향**: 다운타임, 재로그인, 설정 변경처럼 고객이 따로 해야 할 일이 있는지
- **톤**: 공식 공지 톤인지, 조금 더 친근한 뉴스레터 톤인지. 없으면 정중한 공식 톤으로 쓰겠습니다.
- **외부에 공개하면 안 되는 항목**: 내부 리팩터링, 보안 패치 세부 내용 등

## 받으면 이런 형태로 드릴게요

```
[제품명] vX.Y.Z 릴리스 노트 (YYYY-MM-DD)

■ 주요 업데이트 (핵심 1~2개를 고객 가치 중심으로)
■ 새로운 기능
■ 개선 사항
■ 버그 수정
■ 고객 조치 사항 (있을 경우)
■ 문의처
```

그리고 본문과 별도로, 고객사에는 보내지 않는 내부용 메모도 함께 드릴게요.

- **가정**: 제가 추측으로 채운 부분
- **권장 사항**: 표현 수위, 강조할 포인트
- **리스크**: 고객이 오해할 만한 문구, 공개하면 안 될 수 있는 내용
- **다음 할 일**: 발송 전 확인할 것(담당자 검토, 버전 표기 확인 등)

커밋 내용을 붙여 넣어 주시면 바로 작성하겠습니다.
