심사 준비는 도와드릴 수 있습니다. 다만 먼저 분명히 말씀드려야 할 게 있습니다.

## "문제 없음" 확인서는 써드릴 수 없습니다

- 저는 지금 서비스의 구성, 코드, 인프라, 설정, 로그를 전혀 본 적이 없습니다. 확인하지 않은 상태에서 "문제 없음"이라고 쓰면 사실이 아닌 문서가 됩니다.
- 보안 심사 확인서는 보통 **회사(보안 책임자)가 서명하고 책임지는 문서**입니다. AI 답변은 증빙이나 보증이 될 수 없고, 나중에 사고가 나면 오히려 허위 확인으로 문제가 커질 수 있습니다.
- 대신 제가 할 수 있는 일은 이렇습니다: 체크리스트로 **직접 점검**하게 돕기, 부족한 부분 찾기, 증빙 자료 목록 정리, 그리고 **사실만 적은 자가점검 결과서 초안**을 함께 쓰기입니다.

## 꼭 필요한 정보 (5가지)

아래 내용을 알려주시면 체크리스트를 서비스에 맞춰 좁혀 드리겠습니다.

1. **서비스 형태**: 웹 / 모바일 앱 / API / SaaS 중 무엇인지, 어디에 호스팅하는지 (AWS, GCP, 온프레미스 등)
2. **다루는 데이터**: 개인정보, 결제정보, 고객사 기밀 데이터가 있는지
3. **고객사가 요구하는 기준**: 보안 질의서나 기준 문서가 있는지 (예: ISMS-P, ISO 27001, SOC 2, 자체 체크리스트)
4. **이미 갖춘 것**: 인증, 모의해킹 결과, 보안 정책 문서 등
5. **점검할 수 있는 사람**: 누가 실제로 확인하고 서명할지

## 기본 보안 체크리스트 (지금 바로 점검 가능)

각 항목은 **상태(충족 / 부분 / 미충족 / 모름)**와 **증빙 자료**를 함께 적어 두세요.

**1. 계정·접근 관리**
- [ ] 관리자·운영 계정에 MFA 적용
- [ ] 최소 권한 원칙, 퇴사자 계정 즉시 회수
- [ ] 공용 계정 사용 금지, 접근 권한 정기 검토 기록

**2. 인증·세션 (서비스 사용자)**
- [ ] 비밀번호 안전한 해시 저장 (bcrypt/argon2 등)
- [ ] 로그인 실패 제한, 세션 만료, 안전한 쿠키 설정

**3. 데이터 보호**
- [ ] 전송 구간 암호화 (TLS 1.2 이상)
- [ ] 저장 데이터 암호화 (DB, 백업, 스토리지)
- [ ] 개인정보 최소 수집, 보관 기간과 파기 절차

**4. 애플리케이션 보안**
- [ ] OWASP Top 10 기본 대응 (SQL 인젝션, XSS, 접근 제어 누락 등)
- [ ] 의존성·라이브러리 취약점 스캔
- [ ] 코드나 저장소에 비밀키·토큰 하드코딩 없음

**5. 인프라·네트워크**
- [ ] 불필요한 포트나 관리 콘솔이 외부에 노출되지 않음
- [ ] OS·미들웨어 패치 관리
- [ ] 클라우드 스토리지 공개 설정 점검

**6. 로깅·모니터링**
- [ ] 로그인, 권한 변경, 관리자 작업 로그 보관 (기간 명시)
- [ ] 이상 징후 알림

**7. 백업·복구**
- [ ] 정기 백업, **실제 복구 테스트** 기록

**8. 사고 대응**
- [ ] 침해사고 대응 절차 문서, 담당자와 연락망
- [ ] 고객사 통지 절차와 기한

**9. 정책·외부 위탁**
- [ ] 보안 정책, 직원 보안 교육 기록
- [ ] 외부 서비스(SaaS, 수탁사) 목록과 보안 검토

## 가정

- 일반적인 B2B 웹 서비스 기준으로 작성했습니다. 규제 산업(금융, 의료, 공공)이면 항목이 추가됩니다.
- 고객사 질의서가 따로 있다면 그 문서가 이 체크리스트보다 우선입니다.

## 주요 리스크

- **검증 없이 "문제 없음"이라고 제출하는 것** 자체가 가장 큰 리스크입니다. 계약 위반이나 신뢰 문제로 이어질 수 있습니다.
- 일주일 안에 모든 걸 고치기는 어렵습니다. 미충족 항목을 숨기기보다 **개선 계획과 일정**을 함께 내는 편이 심사에서 훨씬 유리한 경우가 많습니다.

## 다음 단계 (심사 전 일주일)

1. **오늘~내일**: 고객사에 질의서나 평가 기준을 요청하고, 위 체크리스트로 자가점검
2. **2~4일차**: 증빙 수집 (설정 캡처, 정책 문서, 로그 보관 설정, 백업 복구 기록). 쉽게 고칠 수 있는 것부터 조치 (MFA, 공개 포트, 비밀키 정리)
3. **5일차**: 미충족 항목은 개선 계획서(조치 내용, 담당자, 완료 예정일)로 정리
4. **6일차**: 책임자가 검토한 뒤 **사실 기반 자가점검 결과서**를 작성하고 서명

위 5가지 정보를 알려주시면 체크리스트를 서비스에 맞게 줄이고, 고객사에 낼 자가점검 결과서 초안(확인된 사항, 조치 중인 사항, 개선 계획)도 함께 만들어 드리겠습니다.
